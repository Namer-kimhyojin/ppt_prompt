# PromptDeck 사이트 전체 개편 설계

- 작성일: 2026-11-14
- 상태: 보류 (2026-11-14 사용자가 진행 중이던 작업 마무리를 우선하기로 함. 승인 전 초안이며 빌더 검토 질문 3개 미해결: 진행 중 작업 처리, 콘텐츠 페이지 CSP 완화, AdSense 승인·광고 단위 ID)
- 범위: 공개 사이트(메인·기능·팁/가이드·소개·정책·AI 업무 도구 허브의 공통 틀)와 작업 앱(`/app`)의 겉모습 전체. 한 번에 개편·배포한다.

## 1. 왜 하는가

사이트가 스스로를 페이지마다 다르게 소개한다. 메인 제목은 "실무 시각자료 프롬프트 설계", 메인 첫 문장은 "발표자료·홍보 이미지, 프롬프트부터 쉽게", 소개 페이지는 "검토 가능한 작업 과정", 기능 페이지는 "결과물에서 작업 메뉴까지"다. 실제 기능은 영상·QR·라벨·문서 디자인까지 넓어졌고 AI 업무 도구(스킬·플러그인·MCP) 허브도 준비 중이다. 방문자가 한 문장으로 기억할 수 없다.

사용자가 정한 정체성: **직장인이 AI를 업무에 쓰는 팁과 서비스를 얻는 곳.**

사용자 목표는 두 가지다. 이 정체성을 사이트 전체에 확립하는 것, 직관적인 인터페이스를 주는 것. 그리고 AI가 만든 티가 나지 않아야 한다. 기능 개선은 목적이 아니다.

추가로 Google AdSense 광고를 넣는다.

## 2. 목표 · 비목표 · 실패 조건

목표

- 모든 공개 페이지와 작업 앱이 같은 정체성 문장, 같은 로고, 같은 디자인 규칙을 쓴다.
- 사이트의 큰 메뉴를 **도구 / 팁 / AI 업무 도구** 세 갈래로 단순화한다.
- 메인은 "무엇을 하는 곳인지"와 "어디로 가면 되는지"를 첫 화면에서 알 수 있게 한다. 팁은 앞으로 꾸준히 쌓이는 콘텐츠로 다루고 메인에 최신 팁이 보이게 한다.
- 작업 앱의 도구 그룹을 결과물 형식이 아니라 **업무 상황**으로 묶어 이름을 바꾼다.
- 콘텐츠 페이지에 광고를 넣는다. 작업 앱에는 넣지 않는다.

비목표

- 도구의 기능·입력 항목·생성 로직·출력물은 바꾸지 않는다. 화면 문구·배치·색·글꼴·간격·그룹 이름만 바꾼다.
- 새 팁 글을 작성하지 않는다. 기존 가이드 4편을 팁으로 재배치하고, 앞으로 글을 쌓을 목록·카드 틀만 만든다.
- AI 업무 도구 허브의 기능(카탈로그 빌드·필터 등)은 별도 작업이다. 이번에는 메뉴 자리와 공통 디자인 규칙만 맞춘다.
- 서비스 이름 PromptDeck은 바꾸지 않는다.

실패 조건 (기술적으로 돌아가도 실패로 본다)

- 화면이 여전히 템플릿처럼 보인다. 이름을 다른 서비스로 바꿔도 어울리는 화면이면 실패다.
- 작업 앱에 광고 코드·광고 자리가 하나라도 들어간다.
- 기존 탭·퀵버튼·모바일 하단 액션바·딥링크(`/app?tab=...`)·가이드 주소가 하나라도 깨진다.
- 광고가 늦게 떠서 본문이 밀린다.

## 3. 디자인 방향

unslop 기준으로 정한 방향. 이후 모든 화면 결정의 기준이다.

- **서비스 한 줄:** 직장인이 보고·발표·홍보 업무에 AI를 쓰도록, 바로 쓰는 도구와 검증된 팁을 주는 곳.
- **성격:** 차분하고, 정확하고, 옆자리 선배처럼 친절함.
- **세계:** 사무실 책상 위 업무 문서. 인쇄한 보고서, 메모, 형광펜.
- **기억에 남는 장면(1~2곳):** 메인 첫 화면에 "원문 메모 → 실제 결과물" 사례. 팁 구역의 대표 팁 1개를 실제 예시와 함께 크게.
- **고유 표시:** 형광펜 밑줄. 화면마다 핵심 문구 한 곳에만 쓴다.

현재 화면에서 고칠 신호 (2026-11-14 로컬 화면 1440×900, 390×844 확인)

| 위치 | 신호 | 고치는 방향 |
|---|---|---|
| 메인 전체 | 도구 9개·단계 4개×2·예시 3개·단계 3개·가이드 3개가 모두 같은 카드 격자 | 구역마다 형태를 다르게. 카드 격자는 도구 찾기 한 곳만 |
| 메인 전체 | 모든 구역이 "작은 파란 머리말 + 큰 제목 + 회색 설명" 반복(7회) | 머리말 제거. 제목은 구체적인 문장 한 줄 |
| 메인 첫 화면 | 실제 결과물 없이 설명 도식만 있음 | 원문 메모가 결과물이 되는 실제 사례를 코드로 구성 |
| 메인 | 업데이트 공지 구역 2개 | 메인에서 제거. 필요하면 팁·소식 목록으로 |
| 작업 앱 | `SLIDE IMAGE VISUAL SPECIFICATION`, `LIVE PREVIEW`, `03 / COPY REQUEST`, `DIRECTION TO AI PRODUCTION` 등 영문 대문자 머리말 | 한국어 문장형 소제목 또는 제거 |
| 작업 앱 | 그룹 탭·하위 탭·결과물 안내 띠 3겹, 안내 띠에 이모지(🖼 ▶ 📄 ⬇ 🎨) | 2겹으로 줄이고 이모지는 한 세트의 선 아이콘 또는 텍스트로 |
| 전체 | 같은 파란색(`--accent: #1f5eff`)이 선택·버튼·단계 번호·배지에 모두 쓰임 | 강조색은 주 행동과 선택 상태에만. 나머지는 중립 단계 |
| 전체 | 메인은 어두운 "P." 로고, 앱은 파란 "PD" 타일 | 하나의 로고로 통일 |

디자인 규칙 (빌더가 정확한 값을 정한다. 아래는 범위)

- 색: 중립색 한 줄을 약간 따뜻한 종이 회색 쪽으로(현재 `--bg: #f3f5f8`는 푸른 회색). 글자는 짙은 남색(현재 `--ink: #132238` 계열 유지). 강조색은 흔한 밝은 파랑 대신 짙은 잉크 블루 하나. 형광펜색은 고유 표시에만. 다크 모드도 같은 구조로.
- 글꼴: Pretendard 유지. 굵기 400·500, 드물게 600. 크기 단계는 몇 개로 제한.
- 간격: 4px 단위. 같은 종류는 같은 크기.
- 모서리: 컨트롤 8~10, 카드 12~16, 안쪽 모서리는 바깥 모서리 − 안쪽 여백.
- 움직임: 반복 애니메이션 없음, 이징 하나, 진입 효과는 최대 1회.
- 문구: 느낌표·과장 표현·짧은 라벨 끝 마침표 없음. 확인할 수 없는 수치 주장 없음.

토큰은 `styles/base.css`의 `:root` 변수를 바꾸는 것이 1차 수단이다. 도구별 CSS(약 4만 4천 줄)는 대부분 이 변수를 쓰므로, 변수 교체 후 하드코딩된 색·대문자 머리말만 찾아 고친다.

## 4. 정보 구조

공개 메뉴: **도구 · 팁 · AI 업무 도구 · 소개** + 주 버튼 "도구 바로 쓰기".

- "기능"(`/features`)은 "도구" 메뉴로 바꾼다. 주소는 유지한다.
- "실무 가이드"(`/guides/`)는 "팁"으로 바꾼다. 주소와 기존 가이드 글 주소는 유지한다(검색 유입 보존). 목록 페이지는 앞으로 글이 늘어나는 것을 전제로 최신순 목록 + 분류로 만든다.
- "AI 업무 도구"(`/ai-tools/`)는 메뉴 자리만 유지한다.

메인 구조

```
[로고]  도구   팁   AI 업무 도구   소개          [도구 바로 쓰기]
───────────────────────────────────────────────────────────
AI로 일하는 직장인을 위한              | 원문 메모 → 실제 결과물
도구와 팁                               | (형광펜 표시가 있는 실제 사례)
[도구 바로 쓰기] [팁 보기]              |
───────────────────────────────────────────────────────────
업무 상황으로 찾기   보고·발표 | 홍보·행사 | 영상 | 인쇄·현장 | 스타일
```

작업 앱 그룹 (기능은 그대로, 묶음과 이름만 변경). 현재: 슬라이드 이미지 / 문서 파일 / 홍보 이미지 / 영상·모션 / 인쇄물 / 스타일.

| 홍보·행사 | 홍보 이미지, 지도·위치도, 사진 스타일 변환 |

이전용 탭(슬라이드 프롬프트(이전), 부속 양식(이전))은 지금처럼 숨긴 상태를 유지한다. 그룹 id(`deckImage` 등)는 저장값·딥링크 호환을 위해 가능하면 유지하고 표시 이름과 소속만 바꾼다. id를 바꿔야 하면 이전 id를 새 id로 옮기는 처리를 둔다.

작업 앱 겉모습

- 헤더: 공개 사이트와 같은 로고·같은 메뉴 링크(도구·팁·AI 업무 도구). 설명 문구는 정체성 문장과 맞춘다.
- 상단 띠: 그룹 탭 + 하위 탭 2겹. 결과물 안내는 띠가 아니라 하위 탭 영역 안의 짧은 한 줄로 옮기거나 각 도구 첫 화면으로 옮긴다.
- `#tabActions`는 `.app-tabs-bar` 안 오른쪽, 모바일은 하단 액션바. CLAUDE.md의 탭 구조·퀵버튼 규칙을 그대로 지킨다.
- 각 도구의 영문 대문자 머리말·이모지·과한 강조색을 정리한다. 도구 내부 입력 구조는 건드리지 않는다.

## 5. 광고

사용자 결정: **콘텐츠 페이지에만 광고.** 메인, 팁·가이드 목록과 글, AI 업무 도구 소개 페이지. 작업 앱(`/app`)은 광고 없음을 유지하고 "작업 화면 광고 없음" 약속도 유지한다.

이미 있는 것: `static-pages/ads.txt`(게시자 `pub-4750696695053294`), `src/adsense.js`·`src/adsense-config.js`(관리자 설정에서 client·slot을 받아 `#mainAdBand`에 표시, `?ad-preview=1` 미리보기), 관리자 설정 화면.

일부러 막아 둔 것: `scripts/deploy-static-release.mjs`와 `scripts/static-smoke-test.mjs`가 앱·정적 결과물에 광고 코드가 있으면 실패시킨다. `static-pages/privacy.html` 5항이 "홈·가이드·/app은 Google 광고 태그를 로드하지 않는다"고 적고 있다.

해야 할 일

- 콘텐츠 페이지 레이아웃에 광고 자리를 정한다. 메인은 첫 화면이 아니라 중간 구역 사이, 팁 글은 도입부 뒤와 글 끝. 광고 단위 ID가 설정된 경우에만 고정 높이 자리를 확보해 늦게 떠도 본문이 밀리지 않게 한다. ID가 없으면 자리를 만들지 않는다.
- 검사 규칙은 "작업 앱에는 광고 없음"을 계속 강제하고, 콘텐츠 페이지에는 허용하도록 바꾼다.
- 개인정보처리방침 5항과 제3자 고지를 개정한다(광고 쿠키·맞춤형 광고·거부 방법). 유럽 등 동의가 필요한 지역은 Google AdSense의 개인정보 보호 및 메시지(동의 관리) 기능을 쓴다.
- 광고는 설정값이 없으면 꺼진 상태로 배포해도 화면이 정상이어야 한다.

## 6. 제약

- CLAUDE.md 규칙: UTF-8(BOM 없음), 큰 파일은 부분 수정, 탭 구조 6요소, 퀵버튼 위치, 탭 바 세로 스크롤바 금지, 한글 깨짐 검사, `node --check`, `git diff --check`, `node scripts/smoke-test.mjs`, 데스크톱·모바일 클릭 검증(특히 지도·부속 양식 탭).
- 배포는 `npm run release:static`. 깨끗한 작업 폴더와 원격에 푸시된 `main`이 필요하고, 모든 테스트 묶음을 실행한다. 현재 이 PC의 wrangler는 Cloudflare에 로그인돼 있지 않아 배포가 막혀 있다(사용자가 `npx wrangler login` 필요).
- 테스트 중 바뀐 문구·그룹 이름을 검사하는 부분은 새 문구에 맞게 고친다. 동작 검사(탭 전환, 복사, 저장, 레이아웃 넘침 등)는 약하게 만들지 않는다.
- 작업 폴더에 다른 진행 중인 작업이 커밋되지 않은 상태로 있다: 영상 에셋(`src/video-asset*.js`, `styles/video-assets.css`, 관련 테스트), 컨셉 믹서, `index.html`·`src/tabs.js` 일부, AI 업무 도구 허브 자료(`content/`, `docs/`). 이번 개편은 같은 파일을 넓게 건드린다.

## 7. 진행 방식 (Approaches)

| 안 | 내용 | 장단점 |
|---|---|---|
| A. 두 단계 | 공개 사이트 먼저, 작업 앱 겉모습은 다음 단계 | 위험이 작지만 잠시 두 모양이 섞임 |
| **B. 한 번에 전체 (선택)** | 공개 사이트와 작업 앱을 함께 바꿔 한 번에 배포 | 처음부터 일관됨. 바뀌는 양과 다른 작업과의 충돌 위험이 큼 |
| C. 디자인 규칙 먼저 | 공통 토큰을 먼저 만들고 화면에 차례로 적용 | 깔끔하지만 결과가 늦음 |

사용자가 B를 선택했다(AI는 A를 추천했음). B 안에서도 작업 순서는 "공통 토큰 → 공통 틀(헤더·메뉴·푸터·로고) → 메인·팁·소개·정책 → 작업 앱 겉모습 → 광고 → 전체 검증"으로 하되 배포는 한 번에 한다.

## 8. 확인 지점

- **시안 승인(구현 초기):** 공통 토큰과 메인 첫 화면, 작업 앱 상단(헤더·탭 띠) 시안을 2~3개 만들어 사용자에게 보여 주고 하나를 고른 뒤 전체에 적용한다.
- **배포 전:** 데스크톱(1440·1280)·모바일(390·375) 화면을 라이트·다크로 캡처해 보여 주고 승인 후 배포한다.

## 9. 빌더에게 맡기는 것

- 정확한 색 값, 글자 크기 단계, 형광펜 표시의 모양.
- 메인 첫 화면 사례에 쓸 예시 내용(실제 도구 결과물 형식을 따르되 가상의 기관·수치임을 밝힌다).
- 선 아이콘 세트 선택(프로젝트에 없으면 lucide).
- 팁 목록의 분류 이름(기존 가이드 4편 기준).
- 결과물 안내 한 줄의 최종 위치.
