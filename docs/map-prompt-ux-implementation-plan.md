# 지도 이미지 프롬프트 UX 개선 구현 계획

## 1. 구현 목표

지도 이미지를 직접 생성하지 않고, 사용자가 특정 구역을 강조하는 최종 결과를 화면에서 계속 유추하면서 상호 모순 없는 이미지 생성 프롬프트를 완성하도록 한다.

핵심 목표는 다음과 같다.

1. 나열형 다중 선택을 결과물 중심의 의사결정 트리로 전환한다.
2. 동시에 성립할 수 없는 강조 방식은 선택 단계에서 차단한다.
3. 연속적인 표현 취향은 의미가 명확한 5단계 슬라이더로 조정한다.
4. 실제 이미지를 생성하지 않아도 SVG 예상도, 결과 요약, 설계 DNA로 결과를 유추할 수 있게 한다.
5. 최종 상태와 프롬프트를 항상 같은 규칙에서 파생해 화면과 출력의 불일치를 방지한다.
6. 기존의 지도 정확성, 허위 지명 금지, 절제된 3D 원칙을 유지한다.
7. 상단의 지도 설명 입력과 하단의 결과 형태·표현 강도 설정을 하나의 단계형 워크플로로 통합한다.

## 2. 비목표

- 지도 파일 업로드 및 이미지 분석
- 이미지 생성 API 연동
- 지도 위 직접 마스킹·다각형 편집
- GIS 데이터 또는 외부 지도 서비스 연동
- 생성 이미지의 OCR·경계 자동 검수

## 3. 사용자 흐름

1. 문서 용도와 지도 맥락을 입력한다.
2. 지도를 통해 가장 먼저 전달할 핵심 메시지를 선택한다.
3. 해당 메시지 아래에서 허용되는 결과 형태 하나를 선택한다.
4. 원본 보존, 정보 밀도, 대상지 집중도, 입체감, 문서 톤을 조정한다.
5. 필요할 때만 허용된 설명 보조 방식 하나를 선택한다.
6. 우측 예상도와 결과 요약을 확인한다.
7. 프롬프트를 확정하고 복사한다.

## 4. 선택 모델

### 4.1 결과 형태 트리

| 핵심 메시지 | 결과 형태 | 기본 강조 기법 | 허용 보조 방식 | 입체감 상한 |
|---|---|---|---|---|
| 대상지 위치 | 경계선 중심 | 경계선 강조 | 콜아웃, 확대 인셋 | 대상지 저입체 |
| 대상지 위치 | 스포트라이트 중심 | 스포트라이트 | 콜아웃, 확대 인셋 | 은은한 레이어 |
| 대상지 위치 | 대상지 저입체 | 경계선, 대상지 리프트업 | 콜아웃 | 대상지 저입체 |
| 교통·거점 연결 | 도로·철도 접근축 | 경계선, 접근축 | 콜아웃, 확대 인셋 | 낮은 아이소메트릭 |
| 교통·거점 연결 | 거점 네트워크 | 경계선, 접근축, 데이터 레이어 | 콜아웃 | 낮은 아이소메트릭 |
| 배후권역·영향 | 영향권 중심 | 경계선, 영향권 | 콜아웃 | 대상지 저입체 |
| 배후권역·영향 | 시설·데이터 분포 | 경계선, 데이터 레이어 | 콜아웃, 확대 인셋 | 대상지 저입체 |
| 후보지 비교 | 동일 기준 비교 | 경계선, 데이터 레이어, 콜아웃 | 확대 인셋 | 은은한 레이어 |
| 사업 전후·성과 | 전후 비교 | 계획 전후, 경계선 | 콜아웃 | 은은한 레이어 |

### 4.2 표현 슬라이더

- 원본 보존: 원본 그대로 → 정돈 → 균형 → 스타일 보정 → 적극적 재해석
- 정보 밀도: 핵심만 → 간결 → 균형 → 상세 → 분석형
- 대상지 집중도: 주변 맥락 → 약한 강조 → 균형 → 강한 강조 → 대상지 최우선
- 입체감: 평면 → 은은한 레이어 → 대상지 저입체 → 낮은 아이소메트릭 → 보드형 3D
- 문서 톤: 공공 보고서 → 절제 → 균형 → 고급 제안 → 설득형 제안

모든 단계에서 실제 지리 구조 보존은 해제되지 않는다.

## 5. 상충 방지 규칙

1. 핵심 메시지와 결과 형태는 각각 하나만 선택한다.
2. 결과 형태가 기본 강조 기법을 결정하며, 사용자가 개별 기법을 임의로 중복 선택하지 않는다.
3. 설명 보조 방식은 현재 결과 형태가 허용한 항목 중 최대 하나만 선택한다.
4. 사업 전후 구성에서는 영향권, 데이터 레이어, 과도한 3D를 함께 사용하지 않는다.
5. 스포트라이트와 영향권처럼 면 채움이 경쟁하는 강조 방식은 동시에 사용하지 않는다.
6. 3D를 사용하지 않으면 카메라 설정을 비활성화한다.
7. 입체감은 결과 형태별 상한을 초과할 수 없으며 초과 입력은 상한값으로 보정한다.
8. 보정이 발생하면 변경 이유를 사용자에게 알리고 예상도와 프롬프트를 즉시 동기화한다.
9. `AI 위임`은 고정 스타일값이 아니라 입력 맥락에 맞춰 적합한 표현을 고르라는 가이드 문장으로 출력한다.

## 6. 예상 문제와 대응

| 예상 문제 | 영향 | 대응책 |
|---|---|---|
| 트리 단계가 늘어나 작업이 길게 느껴짐 | 초기 이탈 | 첫 결과 형태를 목적별 추천값으로 미리 선택하고, 한 화면에서 경로를 확인하게 한다. |
| 자동 보정이 사용자의 선택을 임의로 바꾼다고 느껴짐 | 신뢰 저하 | 보정 사유, 변경된 항목, 적용 상한을 상태 메시지에 명시한다. |
| 슬라이더가 내부의 여러 세부 옵션을 바꿔 결과를 이해하기 어려움 | 예측 가능성 저하 | 단계 이름, 한 줄 효과 설명, SVG 예상도, 설계 DNA를 동시에 갱신한다. |
| 기존 세부 옵션을 찾기 어려움 | 숙련 사용자 불편 | 세부 설정은 `고급 설정` 영역에 유지하되 충돌 규칙의 통제를 받게 한다. |
| SVG 예상도가 실제 모델 결과로 오해됨 | 기대 불일치 | `구성 예상도이며 실제 생성 결과가 아님`을 명시한다. |
| 결과 형태 변경 시 사용자가 작성한 텍스트가 사라짐 | 데이터 손실 | 트리 변경은 시각 설정만 갱신하고 지도 설명, 대상지, 사업 메시지, 라벨 텍스트는 유지한다. |
| 모바일에서 트리와 슬라이더가 길어짐 | 조작 피로 | 카드 1열, 축약 설명, 결과 요약 우선, 고급 설정 접기 구조를 사용한다. |
| 프롬프트 자동 갱신과 `프롬프트 생성` 버튼 역할이 중복됨 | 행동 혼란 | 버튼은 `프롬프트 확정`으로 바꾸고 프롬프트 결과 화면으로 전환하는 역할을 준다. |
| 저장된 이전 상태가 새 상태 구조와 맞지 않음 | 초기화 또는 오류 | 스키마 버전을 저장하고, 유효한 키만 병합하며 잘못된 값은 기본값으로 복구한다. |
| 규칙 추가 후 조합 누락이 발생함 | 숨은 충돌 | 모든 결과 형태에 대해 기본 기법, 보조 방식, 입체감 상한을 데이터로 정의하고 스모크 테스트한다. |
| 지도 설명 입력과 결과 형태 선택이 서로 다른 도구처럼 보임 | 입력 맥락과 표현 설정의 관계를 이해하기 어려움 | `지도 맥락 → 결과 형태 → 표현 강도 → 최종 설정`의 네 단계를 하나의 외곽 표면과 공통 단계 헤더 안에 배치한다. |
| 단계 안내가 새로운 탐색 UI로 오해됨 | 현재 위치나 완료 상태를 잘못 판단 | 진행률이 아니라 작성 순서를 보여주는 동일 위계의 단계 안내로 표현하고, 각 본문 번호와 일치시킨다. |
| 4단계 안내가 모바일에서 과밀해짐 | 텍스트 겹침 및 가로 넘침 | 720px 이하에서 2열로 재배치하고 연결선을 제거하며, 워크플로 전체 폭을 자동 검사한다. |

## 7. 완료 기준

- 결과 형태를 고르면 기본 강조 기법이 자동으로 한 조합으로 결정된다.
- 허용되지 않은 설명 보조 방식은 노출되거나 선택되지 않는다.
- 입체감이 결과 형태의 상한을 초과하지 않는다.
- 3D 미사용 상태에서는 카메라 선택이 비활성화된다.
- SVG 예상도, 결과 요약, 설계 DNA, 프롬프트가 동일한 상태를 반영한다.
- 프롬프트에는 핵심 메시지, 결과 형태, 슬라이더 효과, 지도 정확성 제약이 포함된다.
- 기존 복사, 샘플, 초기화, 3D 샘플 모달 기능이 유지된다.
- 데스크톱에서는 액션 도크가 우측 결과 패널 최상단에 위치한다.
- 모바일에서는 우측 액션 도크가 숨겨지고 본문 액션을 사용할 수 있다.
- 지도 맥락, 결과 형태, 표현 강도, 최종 설정이 하나의 `.map-workflow` 안에서 순서대로 이어진다.
- 모바일에서 4단계 안내가 2열로 전환되고 워크플로 전체가 화면 폭을 넘지 않는다.
- JavaScript 문법 검사, diff 검사, 스모크 테스트, 한글 깨짐 검사를 통과한다.

## 11. 2차 개선 계획: 최종 설정 패널 제거와 3단계 재배치

> 상태: **구현 및 검증 완료**
> 이 절은 현재 4단계 UI를 다음 버전의 3단계 UI로 변경하기 위한 실행 계획이다. 1~10절은 기존 구현 이력으로 유지한다.

### 11.1 개선 목표

1. 독립된 `4. 최종 설정` 패널을 제거한다.
2. 최종 설정의 각 항목을 사용자가 해당 결정을 내리는 1~3단계 가까이에 재배치한다.
3. 슬라이더와 세부 선택값이 같은 개념을 중복 제어하는 느낌을 줄인다.
4. 주요 조정은 항상 노출하고, 숙련자용 세부 조정은 3단계 안의 접이식 영역으로 유지한다.
5. 기존 DOM id, 저장 상태, 프롬프트 생성 규칙과 3D 안전 규칙은 가능한 한 그대로 유지한다.
6. `프롬프트 확정·복사·샘플·초기화`는 설정 단계가 아닌 번호 없는 워크플로 완료 푸터로 분리한다.

### 11.2 목표 사용자 흐름

1. **지도 맥락**: 사업명, 이미지 용도, 출력 규격, 참조 지도, 대상 구역, 사업 메시지를 입력한다.
2. **결과 형태**: 핵심 메시지, 결과 형태, 설명 보조 방식, 실제 표시할 라벨·범례를 결정한다.
3. **표현 조정**: 보존·밀도·집중·입체감·문서 톤을 조정하고 필요한 경우에만 세부 표현과 금지 조건을 수정한다.
4. **워크플로 푸터**: 우측 예상 결과를 확인한 뒤 프롬프트를 확정하거나 복사한다.

상단 작성 순서 안내도 4개에서 다음 3개로 변경한다.

| 단계 | 제목 | 보조 문구 |
|---|---|---|
| 1 | 지도 맥락 | 무엇을·어디에 쓸지 |
| 2 | 결과 형태 | 무엇을 보여줄지 |
| 3 | 표현 조정 | 어떻게 표현할지 |

### 11.4 3단계 세부 조정 구조

슬라이더 카드 안에 다시 큰 카드를 중첩하지 않는다. 슬라이더 5개는 현재처럼 항상 노출하고, 그 아래에 하나의 `표현 세부 조정` disclosure를 둔다.

```text
3. 표현 조정
├─ 원본 보존 슬라이더
├─ 정보 밀도 슬라이더
├─ 대상지 집중도 슬라이더
├─ 입체감 슬라이더
├─ 문서 톤 슬라이더
├─ 표현 세부 조정 (기본 접힘)
│  ├─ 원본 보존: 지도 베이스 / 배경 처리
│  ├─ 정보 밀도: 라벨 밀도
│  ├─ 대상지 집중도: 강조 색상
│  ├─ 입체감: 질감 / 3D 방식 / 카메라 / 샘플
│  └─ 문서 톤: 시각 톤 / 색상 팔레트
└─ 품질·금지 조건
```

disclosure 요약에는 현재 주요값을 `베이스 · 라벨 · 입체감 · 팔레트` 형식의 짧은 요약으로 표시한다. 사용자가 펼치지 않아도 슬라이더가 어떤 세부값을 만들었는지 확인할 수 있어야 한다.

### 11.5 슬라이더와 세부 조정의 동기화 규칙

1. 슬라이더를 1차 조정 수단으로 유지한다.
2. 슬라이더 변경 시 해당 그룹의 세부값을 `PREFERENCE_STEPS` 권장값으로 갱신한다.
3. 세부값을 직접 변경하면 현재 슬라이더 권장값과 비교해 `직접 조정` 상태를 계산한다.
4. `직접 조정` 상태는 별도 저장 플래그를 만들지 않고 현재값과 권장값의 차이로 파생한다.
5. 각 세부 그룹에는 `추천값으로 복원` 기능을 제공한다.
6. 슬라이더를 다시 움직이면 해당 그룹의 직접 조정값은 새 권장값으로 재정렬되며, 상태 메시지로 이를 알린다.
7. 결과 형태별 입체감 상한과 3D 비활성화 규칙은 세부 조정보다 우선한다.
8. 입체감이 0~1이면 3D 방식과 카메라는 비활성화하고 이유를 짧게 표시한다.
9. 결과 요약, 설계 DNA, SVG 예상도, 프롬프트는 정규화된 동일 상태를 사용한다.

### 11.9 예상 문제와 대응

| 예상 문제 | 영향 | 대응책 |
|---|---|---|
| 3단계가 지나치게 길어짐 | 최종 설정을 없앴는데도 조작 피로가 유지됨 | 슬라이더는 항상 노출하고 세부 조정은 기본 접힘, summary에 현재값만 요약한다. |
| 라벨 내용은 2단계, 라벨 밀도는 3단계에 있어 관계가 약해 보임 | 사용자가 두 항목을 같은 기능으로 인지하지 못함 | 2단계에는 `무엇을 표시할지`, 3단계에는 `얼마나 많이 표시할지`라는 보조 문구를 명시한다. |
| 슬라이더 변경으로 직접 고른 세부값이 덮어써짐 | 설정 손실로 인식 | 슬라이더 변경이 새 권장값을 적용한다는 메시지와 그룹별 추천값 복원 상태를 제공한다. |

| 최종 설정 단계가 사라져 완료 시점을 알기 어려움 | 확정 행동을 놓침 | 3단계 뒤에 번호 없는 워크플로 푸터와 우측 결과 패널의 확정 상태를 유지한다. |
| 기존 저장 상태가 초기화됨 | 사용자 데이터 손실 | id와 상태 키를 유지하고 DOM만 이동한다. 스키마 변경이 없으면 v2 저장값을 그대로 복구한다. |
| 기존 자동화가 4단계 구조를 전제로 실패 | 회귀 테스트 실패 | 구조 테스트를 3단계와 새 부모 위치 기준으로 갱신하고 기능 테스트는 그대로 유지한다. |

- 3단계는 슬라이더 중심의 단순한 첫인상을 유지하고 세부 설정은 필요할 때만 펼쳐진다.
- 기존 저장 상태와 프롬프트 내용이 손실되지 않는다.
- 상충 방지, 입체감 상한, 3D 정확성 제약이 이동 전과 동일하게 동작한다.
- 데스크톱과 모바일 모두에서 완료 액션과 우측 결과 확인 흐름이 명확하다.

### 11.12 2차 개선 검증 결과

- 독립된 4단계 패널 제거와 3단계 DOM 순서 검사 통과
- 출력 규격·라벨·세부 설정·금지 조건의 새 부모 위치 검사 통과
- 세부 팔레트 직접 조정 상태와 그룹 추천값 복원 검사 통과
- 사업 전후 결과의 입체감 상한, 3D 컨트롤 비활성화와 사유 안내 검사 통과
- 1440px 육안 점검 및 960px·720px·390px 가로 넘침 자동 검사 통과
- 390px에서 3단계 진행 안내, 세부 설정 1열, 완료 액션 푸터 배치 확인
- 전체 `node scripts/smoke-test.mjs` 통과

## 12. 3차 개선: 설명 가능한 레이어 미리보기

> 상태: **구현 및 검증 완료**
> 범위: 레이어 기반 SVG, 평면/최종 비교, 활성 레이어 인스펙터, 프롬프트 준비 상태 검사

### 12.1 구현 목표

1. 기존 평면 SVG 조각을 동일 좌표계를 공유하는 의미별 레이어 장면으로 재구성한다.
2. 미리보기의 실감도를 높이되 실제 지도 경계와 상대 위치는 변형하지 않는다.
3. 사용자가 어떤 선택이 어떤 시각 레이어를 만들었는지 확인할 수 있게 한다.
4. `평면 기준`과 `최종 연출`을 즉시 비교할 수 있게 한다.
5. 숫자 점수 대신 입력 누락과 위험을 근거로 보여주는 준비 상태 검사를 제공한다.
6. 미리보기와 프롬프트가 동일한 정규화 상태를 사용하게 한다.

### 12.2 레이어 모델

| 순서 | 레이어 | 역할 |
|---|---|---|
| 1 | `base` | 배경, 육지, 행정 구획, 일반 도로 |
| 2 | `context` | 주변 맥락의 명도·채도와 초점 대비 |
| 3 | `analysis` | 접근축, 영향권, 데이터 노드, 비교·전후 정보 |
| 4 | `depth` | 대상지 하부 측면과 저입체 그림자 |
| 5 | `target` | 실제 대상지 경계와 상부 강조 면 |
| 6 | `annotation` | 콜아웃과 확대 인셋 |
| 7 | `labels` | 대상지·거점 라벨과 범례 |
| 8 | `finish` | 보고서 재질, 조명, 가장자리 마감 |

### 12.3 예상 문제와 대응

| 예상 문제 | 대응 |
|---|---|
| 사실적 효과가 허위 지형처럼 보임 | 대상지 상·하부가 동일 polygon을 공유하고 하부만 고정 오프셋한다. |
| SVG 필터로 모바일 렌더링이 느려짐 | 필터 수를 제한하고 큰 blur·상시 애니메이션을 사용하지 않는다. |
| 라벨이 입체 변형으로 흐려짐 | 라벨은 최상단 평면 레이어에 유지한다. |
| 레이어 인스펙터가 실제 on/off 기능으로 오해됨 | 레이어 버튼은 결과를 변경하지 않고 해당 레이어만 강조 표시한다. |
| 평면 비교 모드가 실제 상태를 변경함 | 비교 모드는 미리보기 전용 UI 상태로 두고 프롬프트·저장 상태에 반영하지 않는다. |
| 준비 상태가 품질 보증 점수로 오해됨 | 숫자 점수를 사용하지 않고 `준비 완료/입력 보완/검토 필요`와 근거를 표시한다. |
| 사용자 입력을 SVG 문자열에 삽입하면서 보안 문제가 생김 | SVG 안에는 고정 라벨만 사용하고 사용자 텍스트는 DOM `textContent`로만 표시한다. |
