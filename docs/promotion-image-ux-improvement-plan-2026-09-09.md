# 홍보용 이미지 탭 사용자 편의성·직관성 개선 과제

점검일: 2026-09-09 · 상태: 개선 과제와 구현 기록 · 사용자 승인에 따라 U01~U10 구현

## 1. 판단

가장 큰 개선 기회는 **메시지를 먼저 입력하고, 적용된 내용을 눈으로 확인한 뒤, 같은 결과를 복사·저장·이미지 생성에 사용하는 흐름**을 만드는 것이다.

현재 원문 요약, 빠른 규격, 자동 초안 저장, 컨셉 연계, 프롬프트 편집 등 기반 기능은 있다. 다만 첫 화면의 규격 설정 비중이 크고, 선택지·명칭·출력 상태를 사용자가 해석해야 한다. 편집본 복사·복원 결함도 재현되어, 화면 개편에 앞서 결과의 일관성을 확보할 필요가 있다.

이 문서는 2026-09-04 기능 점검 기록을 참고하되, 아래 확인 결과는 현재 로컬과 공개 화면에서 다시 점검했다. 이전 보고서의 모든 결함을 이번에 전수 재검증한 것은 아니다.

위 위치는 빈 작업 상태, 브라우저 기본 확대율에서 측정한 문서 상단 기준 값이다. 접힘 상태·저장된 입력·글꼴 환경에 따라 달라질 수 있다.

검사는 별도의 브라우저 컨텍스트에서 진행했다. 복사 확인은 클립보드 쓰기 함수에 전달되는 문자열을 포착하여 사용자의 실제 클립보드를 덮어쓰지 않았다. 실제 이미지 API 호출과 최종 이미지 품질 검증은 수행하지 않았다.

## 3. 개선 과제 10건

우선순위: **P0**은 작업 내용·출력 신뢰성, **P1**은 기본 사용 흐름, **P2**는 반복 작업 효율이다. 아래는 최초 점검 때 정한 개선 과제와 완료 기준이며, 승인 후 구현·검증 기록은 7절에 정리했다.

### U01 · P0 · 편집·복사·저장 결과를 일치시키기

- **사용자 문제:** 직접 고친 문구가 화면 전환이나 파일 불러오기 후 적용되지 않는다.
- **개선:** 현재 사용하는 프롬프트를 하나로 정하고 뷰어·전체 복사·섹션 복사·파일 저장·자동 저장·이미지 생성 전달이 함께 사용하게 한다. 자동 초안과 수정본을 유지한다면 현재 선택한 버전을 명시한다. 설정 변경으로 수정본을 교체할 때에는 ‘새 설정으로 다시 만들기’와 실행 취소를 제공한다.
- **완료 기준:** 동일 표식을 전체·섹션 편집에 각각 넣은 뒤 미리보기, 복사, 새로고침, 파일 불러오기, 생성 탭 전달에서 보존한다. 일반 설정 변경도 편집본을 조용히 덮어쓰지 않는다.
- **관련 위치:** `src/promotion.js:4344`, `:5080`, `:5134`, `:5552`, `src/slide-image-generation.js:161`.

### U02 · P1 · 첫 화면을 ‘홍보 내용 입력’ 중심으로 재배치

- **사용자 문제:** 만들 내용보다 규격·저장된 규격·설명부터 읽어야 한다. 샘플 채우기도 입력 폼 맨 아래에 있다.
- **개선:** 첫 화면에 ‘원문으로 채우기 / 직접 입력 / 예시 불러오기’를 배치하고 직접 입력 폼은 즉시 사용할 수 있게 둔다. 제목·대상·핵심 내용을 먼저 보여준다. 규격은 ‘세로형 4:5 · 변경’처럼 요약하고, 로고·QR·세부 품질은 선택 시 펼친다. 기존 원문 요약·샘플 기능의 위치를 바꾸는 방식으로 시작한다.
- **완료 기준:** 1440×1000 및 390×844의 초기 화면에서 원문 입력 시작 버튼과 제목 입력란이 보인다. 상세 설정을 열지 않고도 기본 초안을 만들 수 있다.
- **관련 위치:** `index.html:642`, `:649`, `:773`, `:811`, `partials/pane-promotion.html`.

### U03 · P1 · 원문 요약을 ‘붙여넣기 → 확인 → 적용’으로 정리

- **사용자 문제:** 분석 전부터 선택 항목 적용 버튼이 보인다. 추출한 정보가 어디에 반영되는지 확인하기 어렵다.
- **개선:** 현재 단계만 보이게 하고 분석 전 적용 버튼은 숨긴다. 결과는 제목·일정·대상·혜택 등 이미지에 들어갈 문구 중심으로 보여주고 근거·신뢰도는 필요할 때 펼친다. 이미 작성한 내용의 교체 여부, 꺼진 항목의 활성화 여부를 적용 내역에 명시한다. Escape 닫기와 닫은 뒤 호출 버튼으로 포커스 복귀를 제공한다.
- **완료 기준:** 각 단계에 주요 실행 버튼이 하나만 보인다. 선택한 문구의 사용 상태와 최종 반영 내용이 일치한다. Tab 탐색이 대화상자 밖으로 이탈하지 않는다.
- **관련 위치:** `src/promotion.js:2408`, `:3214`, `styles/promotion.css:452`.

### U04 · P1 · 명칭과 자동 동작을 사용자 언어로 통일

- **사용자 문제:** CTA·오퍼·훅, AI 자동, 초안 반영, 미리보기의 의미를 사용자가 추측해야 한다. 컨셉 이동 버튼은 실제 목적지와도 다르다.
- **개선:** 아래 표현을 적용하고 필요할 때 전문 용어를 보조 설명으로 제공한다.

| 현재 표현 | 제안 표현·설명 |
|---|---|
| 헤드라인 / 서브 카피 | 제목 / 보조 설명 |
| 엑션버튼(CTA) | 참여 유도 문구 — 예: 지금 신청하기 |
| 한 줄 오퍼 / 첫 줄 훅 | 핵심 혜택 / 시선을 끄는 첫 문장 |
| AI가 자동으로 생성합니다 | 이미지 생성 시 AI가 작성합니다 |
| 초안 반영 | 자동 초안으로 되돌리기 |
| ← 미리보기 | 프롬프트 보기. 향후 구성 참고도를 추가하면 별도 이름 사용 |
| 컨셉 제안으로 이동 | 비주얼 믹서에서 선택 |
| Edit / Save / Cancel / Copy | 편집 / 적용 / 취소 / 복사 |
| 저장 / 불러오기 | 작업 파일 저장 / 작업 파일 열기 |

- **완료 기준:** 버튼명이 실제 동작·이동 탭과 일치한다. AI 자동을 선택해도 이 화면에서 문구가 즉시 생성되는 것은 아니라는 점을 짧은 안내만으로 이해할 수 있다. 품질·토큰 같은 정보는 사용자가 결정할 일이 있을 때 상세 영역에서 설명한다.
- **관련 위치:** `src/promotion.js:4290`, `:4418`, `:5525`, `index.html:938`, `:1192`, `:1223`.

### U05 · P1 · 결과 영역에 ‘이미지에 들어갈 내용’과 구성 참고도 제공

- **사용자 문제:** 오른쪽은 긴 영문 프롬프트가 대부분이며, 이미지에 어떤 문구가 들어가고 어느 부분을 수정해야 할지 바로 알기 어렵다. 초기 빈 상태에도 약 3,859자의 초안이 표시된다.
- **개선:** 결과 상단에 한국어 제목·보조 문구·혜택·참여 문구와 규격을 먼저 표시한다. 제목·비주얼·본문·로고·QR 위치를 보여주는 간단한 구성 참고도를 제공한다. 영문 프롬프트는 별도 보기·편집으로 전환한다. 구성 참고도에는 실제 생성 결과와 다를 수 있다는 설명을 붙인다.
- **완료 기준:** 프롬프트를 읽지 않고도 포함할 문구, 규격, QR·로고 공간 여부를 확인할 수 있다. 항목 선택으로 해당 입력란을 수정할 수 있고 수정 결과가 요약·프롬프트에 함께 반영된다.
- **관련 위치:** `index.html:1200`, `:1235`, `src/promotion.js:4344`, `styles/promotion.css`.

### U06 · P1 · 결과 활용 버튼과 다음 단계 연결을 단순화

- **사용자 문제:** 레이아웃 변경 버튼이 도크와 결과 내부에 중복되고 ‘기관용 비주얼 바꾸기’ 등이 복사와 함께 강조된다. 이미지 생성으로 이어가는 방법은 다른 탭의 ‘현재 프롬프트 가져오기’를 알아야 한다.
- **개선:** 우측 도크는 ‘프롬프트 복사 / 이미지 생성으로 보내기 / 더보기’로 정리한다. 레이아웃 변경은 해당 설정 근처에 두고 저장·불러오기·초기화는 더보기에 묶는다. ‘이미지 생성으로 보내기’는 현재 유효한 프롬프트를 채워 생성 탭으로 이동시키고, 실제 생성 실행은 생성 탭에서 진행한다.
- **완료 기준:** 결과에서 한 번의 클릭으로 동일한 프롬프트가 이미지 생성 탭에 채워진다. 복사 성공은 바로 확인할 수 있고, 중복 레이아웃 액션이 없다. 도크는 탭 바가 아닌 활성 탭 우측 패널 상단에 유지한다.
- **의존:** U01 선행.
- **관련 위치:** `src/tabs.js:166`, `index.html:2836`, `src/slide-image-generation.js:161`.

### U07 · P1 · 입력 안내·경고·완료 알림을 실제 동작에 맞추기

- **사용자 문제:** 시작하자마자 오류 표시가 보이고, 복사 불가 안내와 실제 동작이 다르다. 복사·저장 결과 메시지의 표시 대상도 없다.
- **개선:** 빈 첫 화면에는 ‘제목부터 입력해 주세요’ 같은 안내를 표시한다. 필드 수정 후 또는 결과 사용 시 필요한 오류를 해당 필드 가까이 보여준다. 복사 정책은 완성본과 미완성 초안으로 구분해 안내와 동작을 맞춘다. 복사·적용·저장·복원에는 짧고 일관된 알림과 보조기기용 상태 알림을 연결한다. 자동 저장 시 마지막 저장 시각을 표시한다.
- **완료 기준:** 동작이 차단되면 이유와 수정 위치를 바로 찾을 수 있다. 미완성 초안을 허용하면 그 상태를 명시한다. 저장 실패를 성공으로 표시하지 않는다.
- **관련 위치:** `src/promotion.js:920`, `:1356`, `:2009`, `:5149`.

### U08 · P1 · 모바일 ‘입력 / 결과’ 이동과 터치 영역 개선

- **사용자 문제:** 입력 끝까지 이동해야 결과를 볼 수 있고, 결과를 확인하지 않은 상태에서도 하단 복사가 강조된다. 작은 규격 칩은 누르기 어렵다.
- **개선:** 모바일에 ‘입력 / 결과’ 전환을 제공하고 입력 위치·내용을 보존한다. 초기 하단 액션은 ‘결과 확인’, 결과 화면에서는 ‘프롬프트 복사’를 우선한다. 설정을 바꾼 경우 결과 갱신 여부를 알린다. 주요 터치 영역은 44px 이상을 제품 목표로 잡는다.
- **완료 기준:** 입력 중 한 번에 결과로 이동하고 같은 입력 위치로 돌아올 수 있다. 360·390px에서 가로 넘침·하단 가림 없이 이용할 수 있고, 키보드를 열어도 현재 입력과 주요 액션에 접근할 수 있다.
- **관련 위치:** `styles/promotion.css:3936`, `:4722`, `src/tabs.js`, 모바일 공통 액션 로직.

### U09 · P2 · 추천 비주얼을 비교하고 선택하게 만들기

- **사용자 문제:** 기본 스타일·랜덤 프리셋·기관용 랜덤 비주얼·추천 화풍·다른 탭 이동 등 선택 경로가 여러 곳에 있다. 선택 전에 변화 범위를 예상하기 어렵다.
- **개선:** 홍보 내용 근처에서 추천 비주얼 3개와 썸네일, 짧은 추천 이유를 보여준다. ‘더 자세히 선택’으로 비주얼 믹서에 연결한다. 비주얼 변경은 문구·규격을 유지하고 이전 스타일로 되돌릴 수 있게 한다. 목적과 무관한 추천 여부는 별도 사례 검증으로 보완한다.
- **완료 기준:** 각 추천의 시각적 차이와 변경 범위가 보인다. 적용 전후에 제목·날짜·QR URL·규격이 유지된다. 복원 후에도 선택한 비주얼을 다시 편집할 수 있다.
- **관련 위치:** `src/promotion.js:867`, `:5042`, `:5500`, `src/promotion-data.js`.

### U10 · P2 · 자주 쓰는 규격·작업을 정확하게 재사용

- **사용자 문제:** 비율·방향·직접 크기·빠른 규격·내 규격이 동시에 노출되고, 사용자 지정 비율은 저장 후 복원되지 않는다. 자동 저장과 파일 저장의 차이도 보이지 않는다.
- **개선:** 채널·용도에 맞는 대표 규격과 실제 숫자를 함께 보여준다. 직접 입력은 상세 설정으로 묶는다. 사용자 지정 규격의 실제 너비·높이를 보존하고 `custom 세로` 대신 저장한 수치를 표시한다. 브라우저 자동 저장, 작업 파일, 규격 프리셋의 범위를 명확히 나눈다. 반복 작업에는 이름 붙인 템플릿과 복제 흐름을 제공한다.
- **완료 기준:** 21:29.7 등 사용자 지정 규격을 저장·변경·재적용·새로고침해도 값이 같다. 규격만 적용하면 문구는 바뀌지 않는다. 인쇄용이라고 안내하는 프리셋은 실제 규격과 일치해야 한다.
- **우선 처리:** 확인된 비율 복원 결함은 P2 기능 확장을 기다리지 않고 U01과 같은 신뢰성 정비 단계에서 수정한다.
- **관련 위치:** `src/promotion.js:1129`, `:1146`, `:5070`, `index.html:717`.

## 4. 권장 사용 흐름

**홍보 내용 입력 → 비주얼·규격 확인 → 이미지에 들어갈 내용 확인 → 프롬프트 복사 또는 이미지 생성으로 보내기**

- 진입 시 제목 입력란과 원문 입력 버튼을 함께 제공해 즉시 작업을 시작한다.
- 규격은 기본값을 바로 쓰되 현재 값을 항상 요약 표시한다.
- 로고·QR은 실제 자산 삽입 여부와 공간 설계 여부를 항목 안에서 설명한다. 현재 안내를 유지하면서 기능 이름도 실제 역할에 맞춘다.
- ‘자동 / 직접 입력 / 사용 안 함’은 복수 스위치보다 현재 상태가 하나로 읽히는 선택 구조로 통일한다.
- 결과 요약에서 문구를 확인하고 필요할 때 프롬프트 전문을 편집한다.

## 6. 구현 시 검증 범위

- 편집·복사·저장·복원·전달 경로에 동일한 표식을 사용하는 행동 검증을 추가한다. 기존 파서 검사만으로 완료 판단하지 않는다.
- 요약 창은 `hidden` 속성 유무뿐 아니라 실제 가시성, 키보드 이동, 적용 결과를 확인한다.
- UI 변경 시 `index.html`과 `partials/pane-promotion.html`을 각각 확인한다. 현재 두 파일의 홍보 탭 구성이 완전히 같은 것은 아니므로 partial을 그대로 빌드하여 최근 변경을 덮어쓰지 않도록 먼저 동기화 범위를 검토한다.
- 관련 JS 문법 검사, `git diff --check -- index.html src styles`, `node scripts/smoke-test.mjs`, `node scripts/promotion-parser-test.mjs`를 수행한다. 공통 탭 액션을 바꾸면 지도 이미지·부속 양식 탭도 클릭 검증한다.
- 데스크톱·모바일에서 첫 입력 접근, 결과 이동, 저장 복원, 가로 넘침, 액션 도크 위치를 확인한다.
- 최초 점검은 문서 작성까지였으며, 이후 사용자의 구현·배포 승인에 따라 아래 작업을 진행했다.

검증은 `npm run promotion:test`에 파서 검사와 실제 브라우저 사용자 흐름 검사를 함께 등록했다. 편집·복사·파일 복원·새로고침·섹션 편집·실행 취소·생성 탭 전달, 규격·템플릿 복원, 요약 대화상자 키보드 조작, 추천 적용, 360·390px 결과 전환을 통과했다. JS 문법·UTF-8 without BOM·diff 공백 검사도 수행했다.

공통 탭 변경은 전체 `smoke:test`와 배포용 정적 검사로 재검증한다. `release:static`에 홍보 탭 검사를 추가하고, 운영·배포 고유 URL에서 새 홍보 JS/CSS의 SHA-256 검증을 필수화했다. 원래 작업 폴더의 다른 탭 변경은 배포 범위에서 제외한다.

구성 참고도는 실제 생성 이미지가 아니다. 실제 이미지 생성 API 호출과 최종 생성 이미지 품질 평가는 이번 UI 검증 범위에 포함하지 않는다.
