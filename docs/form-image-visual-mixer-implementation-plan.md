# 양식 이미지 탭 구현계획서

## 1. 목표

기존 `비주얼 믹서` 탭은 그대로 활용하고, 기존 `부속 양식` 탭은 변경하지 않는다. 새 상위 탭 `양식 이미지`를 추가하여, 비주얼 믹서에서 만든 스타일 조합을 문서 표지, 문서 간지, 문서 배경, 안내판 이미지 프롬프트로 고도화한다.

핵심 흐름은 다음과 같다.

```text
비주얼 믹서 -> 양식 이미지에 적용 -> 양식 이미지 탭 -> 프롬프트 복사 또는 이미지 생성 탭 전달
```

`양식 이미지` 탭은 기존 `부속 양식`의 정형 입력 폼을 대체하지 않는다. 대신 홍보용 이미지 탭처럼 비주얼 믹서 결과를 받아 고품질 이미지 생성 프롬프트로 번역하는 전용 작업 공간으로 만든다.

## 2. 제품 방향

`홍보용 이미지`가 모집, 행사, 광고처럼 눈에 띄는 한 장을 만드는 도구라면, `양식 이미지`는 문서와 발표자료에 붙는 보조 이미지를 일관된 시각 시스템으로 만드는 도구다.

따라서 새 탭의 중심 가치는 다음과 같다.

- 문서 표지, 간지, 배경, 안내판을 같은 스타일 언어로 묶는다.
- 비주얼 믹서의 화풍과 팔레트를 문서용 가독성 기준에 맞게 절제한다.
- 표지는 강하게, 간지는 중간 강도, 배경은 낮은 강도, 안내판은 정보 안내성이 높게 변환한다.
- 실제 문서/PPT에서 후편집 가능한 여백과 텍스트 영역을 보존한다.
- 기존 `부속 양식` 탭의 안정적인 기능은 그대로 둔다.

## 3. 탭 구조

신규 탭명은 `양식 이미지`로 한다.

권장 ID와 파일 구조는 다음과 같다.

```text
index.html
  tabBtnFormImage
  paneFormImage

src/tabs.js
  formImage 탭 등록
  actionSets.formImage 등록

src/form-image.js
styles/form-image.css
```

기존 `부속 양식` 탭 관련 파일은 유지한다.

```text
tabBtnSlideDocument
paneSlideDocument
src/slide-document.js
styles/slide-document.css
```

## 4. 비주얼 믹서 연동 방식

기존 `비주얼 믹서` 결과 카드에 새 버튼을 추가한다.

```text
프롬프트 복사
홍보 이미지에 적용
양식 이미지에 적용
부속 양식에 적용
```

`부속 양식에 적용`은 기존 연동 기능 보존용으로 남긴다. 새 기능은 `양식 이미지에 적용` 버튼으로 분리한다.

신규 전역 함수는 다음 형태를 사용한다.

```js
window.applyMixerToFormImage = function (mixerData) {
  // form-image.js에서 구현
};
```

비주얼 믹서에서 전달할 데이터는 기존 `홍보용 이미지`와 `부속 양식` 연동 데이터를 최대한 재사용한다.

```js
{
  nameKo,
  nameEn,
  prompt,
  subjectKo,
  subjectEn,
  mediumKo,
  mediumEn,
  mediumRendering,
  palette,
  colorRoles,
  textureInfo,
  layoutFeel,
  typographyGuidance,
  promptParts
}
```

`applyMixerToFormImage`는 데이터를 탭 상태에 저장하고, `tabBtnFormImage.click()`으로 새 탭을 활성화한다.

## 5. 세트 구성

`양식 이미지` 탭의 세트 생성에는 반드시 아래 4종을 포함한다.

1. 문서 표지
2. 문서 간지
3. 문서 배경
4. 안내판

세트 생성 시 같은 비주얼 믹서 스타일을 기반으로 하되, 각 산출물의 목적에 따라 적용 강도와 레이아웃 제약을 다르게 둔다.

| 산출물 | 적용 강도 | 핵심 목적 | 주요 제약 |
| --- | --- | --- | --- |
| 문서 표지 | 강함 | 첫인상, 주제 상징, 신뢰감 | 제목 영역 선명, 기관명/메타 정보 자리 확보 |
| 문서 간지 | 중간 | 섹션 전환, 장 구분 | 섹션명 판독성, 과한 장식 금지 |
| 문서 배경 | 낮음 | 본문 편집 공간, 분위기 | 텍스트 없음, 낮은 대비, 중앙 여백 확보 |
| 안내판 | 중상 | 방향 안내, 절차 안내, 정보 고지 | 정보 블록 구조, 아이콘/화살표 자리, 명확한 위계 |

## 6. UI/UX 설계

### 6.1 전체 레이아웃

데스크톱에서는 2열 구조를 사용한다. 3열은 정보가 분산되어 복잡해질 수 있으므로, 설정과 결과를 명확히 나눈다.

```text
[왼쪽 작업 패널] [오른쪽 결과 패널]
```

- 왼쪽 작업 패널: 양식 종류, 기본 문구, 분위기/용도 메모, 비주얼 믹서 스타일 요약, 적용 강도 조절
- 오른쪽 결과 패널: 최종 프롬프트, 세트 결과, 복사, 이미지 생성 전달

모바일에서는 단일 컬럼으로 접는다.

```text
작업 설정 -> 결과 프롬프트
```

상단 `#tabActions`는 모바일에서 숨기고, 기존 모바일 하단 액션바 정책을 따른다.

### 6.2 상단 퀵버튼

`src/tabs.js`의 `actionSets.formImage`에 아래 버튼을 등록한다.

```text
세트 생성
프롬프트 복사
이미지 생성으로 보내기
초기화
```

각 퀵버튼은 실제 탭 내부 버튼을 프록시한다.

```text
formImageGenerateSetBtn
formImageCopyPromptBtn
formImageSendToImageBtn
formImageResetBtn
```

### 6.3 왼쪽 작업 패널

필수 입력 항목:

- 생성 방식
  - 단일 이미지
  - 세트 이미지
- 양식 종류
  - 문서 표지
  - 문서 간지
  - 문서 배경
  - 안내판
- 텍스트 처리
  - 텍스트 자리만 확보
  - 실제 텍스트 포함
  - 텍스트 없이 배경만
- 제목/섹션명/기관명
- 분위기/용도 메모
- 추가 요구사항

안내판 선택 시 추가 항목:

- 안내판 목적
  - 행사장 안내
  - 절차 안내
  - 방향 안내
  - 프로그램 안내
  - 주의/공지
- 정보 구조
  - 제목 + 3개 정보 블록
  - 제목 + 화살표/방향
  - 제목 + 일정/장소
  - 제목 + 단계형 절차
- 아이콘 사용 여부
- QR/로고 자리 확보 여부

왼쪽 작업 패널 하단에는 비주얼 믹서 연동 상태를 함께 배치한다. 별도 중앙 컬럼을 만들지 않고, 입력 흐름 안에서 현재 스타일을 확인하고 바꿀 수 있게 한다.

### 6.4 비주얼 믹서 스타일 영역

비주얼 믹서 연동 전에는 빈 상태를 보여준다.

표시 내용:

```text
아직 적용된 비주얼 믹서 스타일이 없습니다.
[비주얼 믹서로 이동]
[샘플 스타일 적용]
```

비주얼 믹서 연동 후에는 다음 정보를 요약한다.

- 스타일명
- 주제
- 화풍/렌더링
- 팔레트 스와치
- 구성 감각
- 타이포그래피 가이드

제공 액션:

- 비주얼 믹서로 이동
- 연동 해제
- 랜덤 비주얼 적용
- 현재 스타일로 세트 생성

### 6.5 적용 강도 조절

기본값은 산출물별 자동 강도를 사용한다.

```text
표지: 강함
간지: 중간
배경: 낮음
안내판: 중상
```

사용자가 직접 바꿀 수 있도록 segmented control을 제공한다.

```text
낮음 / 균형 / 강함
```

세트 모드에서는 각 산출물별 강도 행을 보여준다.

```text
표지      [낮음] [균형] [강함]
간지      [낮음] [균형] [강함]
배경      [낮음] [균형] [강함]
안내판    [낮음] [균형] [강함]
```

### 6.6 오른쪽 결과 패널

단일 이미지 모드:

- 최종 프롬프트 textarea
- 품질 체크 리스트
- 복사 버튼
- 이미지 생성 탭으로 보내기 버튼

세트 이미지 모드:

- 탭 또는 아코디언으로 4종 결과 표시
  - 표지
  - 간지
  - 배경
  - 안내판
- 전체 복사
- 현재 항목 복사
- 이미지 생성 탭으로 현재 항목 보내기

결과 패널에서는 생성 조건을 직접 설명하는 장문 도움말을 과하게 넣지 않는다. 대신 상태 배지와 짧은 라벨로 충분히 이해되게 한다.

## 7. 프롬프트 생성 정책

### 7.1 공통 프롬프트 원칙

모든 산출물에 다음 제약을 포함한다.

- 실제 사용 가능한 문서/PPT 양식 이미지로 보이게 한다.
- 텍스트 영역과 편집 여백을 보존한다.
- 불필요한 가짜 로고, 워터마크, 임의 QR코드, 임의 세부 텍스트를 만들지 않는다.
- 사용자가 입력한 텍스트 외에는 긴 문장을 이미지 안에 생성하지 않는다.
- 비주얼 믹서 스타일은 문서 목적에 맞게 절제해 적용한다.

## 7A. 표지 입력 구조 고도화 계획

표지는 문서 세트의 첫인상을 결정하는 메인 비주얼이다. 따라서 단순히 제목/부제/기관명을 받는 방식으로는 부족하다. 공통 입력은 모든 양식에 반복되는 최소 정보로 유지하고, 표지 탭에는 표지의 시선 흐름, 텍스트 위계, 메인 비주얼, 발표 정보, 기관 로고 배치를 다루는 전용 입력을 둔다.

### 7A.1 공통 입력으로 유지할 항목

공통 입력은 표지뿐 아니라 간지, 배경, 안내판에도 의미가 있는 정보만 둔다.

- 프로젝트/문서명
  - 예: `2026 지역혁신 지원사업`
  - 표지에서는 기본 제목 후보가 된다.
  - 간지에서는 문서 세트의 상위 맥락으로만 사용한다.
  - 배경에서는 직접 텍스트로 넣지 않고 스타일 맥락으로만 쓴다.
- 공통 보조 문구
  - 예: `추진 성과 및 향후 계획`
  - 표지에서는 부제 후보가 된다.
  - 간지에서는 섹션 설명의 fallback으로만 쓴다.
- 기관명
  - 표지/안내판에서 표시 후보가 된다.
  - 배경에서는 로고나 텍스트를 직접 만들지 않도록 제약에 사용한다.
- 이미지 안 글자 처리
  - `글자 자리만 비워두기`
  - `입력한 글자 넣기`
  - `글자 없이 만들기`
- 원하는 느낌
  - 예: `공공기관 자료처럼 차분하고 신뢰감 있게`
  - 모든 산출물에 적용되는 톤이다.
- 꼭 지킬 점
  - 예: `중앙 텍스트 영역은 넓게 비워두기`
  - 모든 산출물에 적용되는 제약이다.

### 7A.2 표지 전용 입력으로 분리할 항목

표지 전용 영역은 `표지에 들어갈 정보`와 `표지 설계 전략`으로 나눈다.

#### A. 표지에 들어갈 정보

- 표지 제목
  - 비워두면 공통 `프로젝트/문서명`을 사용한다.
  - 프롬프트에서는 `Cover title`로 반영한다.
- 표지 부제
  - 비워두면 공통 `공통 보조 문구`를 사용한다.
  - 프롬프트에서는 `Cover subtitle`로 반영한다.
- 발표일/작성일
  - 예: `2026.07.05`, `2026년 7월`
  - 실제 텍스트 포함 모드일 때만 렌더링 대상으로 명시한다.
  - 자리만 확보 모드에서는 날짜/버전 정보 영역으로만 지시한다.
- 발표자/작성자
  - 예: `전략기획팀 김OO`, `홍길동 책임연구원`
  - 너무 길 경우 작은 메타 영역에 배치하도록 지시한다.
- 부서/행사/과정명
  - 예: `전략기획팀`, `성과공유회`, `실무자 교육 과정`
  - 제목보다 낮은 위계로 사용한다.
- 표지 메타 정보
  - 자유 입력 fallback.
  - 날짜, 버전, 부서, 작성자 등을 한 줄로 넣고 싶은 사용자를 위해 유지한다.

#### B. 표지 설계 전략

- 표지 강조 방식
  - `텍스트 중심`
    - 제목 판독성과 정보 신뢰감을 최우선.
    - 비주얼은 배경/보조 장식으로 처리.
  - `비주얼 중심`
    - 메인 오브젝트나 상징 이미지를 강하게 배치.
    - 제목은 명확한 영역에 얹는다.
  - `균형형`
    - 제목과 비주얼을 5:5에 가깝게 배치.
    - 기본 추천값.
  - `로고/기관 신뢰 중심`
    - 기관명, 로고 자리, 공식 문서 느낌을 강조.

- 제목 배치
  - `좌측 정렬`
  - `중앙 정렬`
  - `상단 배치`
  - `하단 배치`
  - `AI 위임`
    - 고정값을 넘기지 않고, 제목 길이와 비주얼 방향에 맞춰 최적 배치를 고르도록 지시한다.

- 메인 비주얼 위치
  - `우측`
  - `좌측`
  - `중앙`
  - `배경 전체`
  - `코너 장식`
  - `AI 위임`

- 텍스트 영역 보호
  - `넓게 확보`
  - `보통`
  - `최소`
  - 제목이 길거나 실제 텍스트 포함 모드일수록 자동으로 `넓게 확보`를 추천한다.

- 로고 사용 여부
  - `로고 자리 없음`
  - `기관명 텍스트만`
  - `로고 자리 확보`
  - `로고 + 기관명 자리 확보`
  - 실제 로고 이미지를 생성하지 않고, 빈 로고 영역이나 placeholder만 지시한다.

- 로고 배치
  - `좌상단`
  - `우상단`
  - `좌하단`
  - `우하단`
  - `하단 바`
  - `AI 위임`

- 표지 정보 밀도
  - `미니멀`
    - 제목/부제 정도만.
  - `표준`
    - 제목, 부제, 기관명, 날짜 정도.
  - `상세`
    - 발표자, 부서, 버전/행사명까지 포함.

### 7A.3 표지 UI 구성안

표지 선택 시 `2. 어떤 내용이 들어가나요?` 카드 안에 다음 순서로 표시한다.

```text
[공통 정보]
프로젝트/문서명
공통 보조 문구
기관명
이미지 안 글자

[표지에 들어갈 정보]
표지 제목
표지 부제
발표일/작성일
발표자/작성자
부서/행사/과정명
표지 메타 정보

[표지 설계 전략]
강조 방식
제목 배치
메인 비주얼 위치
텍스트 영역 보호
로고 사용 여부
로고 배치
정보 밀도
```

단일 표지 모드에서는 표지 전용 패널만 펼친다. 세트 모드에서는 표지 패널을 가장 위에 두되, 접을 수 있는 형태로 두어 간지/배경/안내판 입력과 과도하게 경쟁하지 않게 한다.

### 7A.4 표지 상태 데이터 설계

`src/form-image.js`의 표지 관련 상태는 아래처럼 확장한다.

```js
cover: {
  title: "",
  subtitle: "",
  date: "",
  presenter: "",
  department: "",
  meta: "",
  emphasis: "balanced", // text_focus | visual_focus | balanced | institutional
  titlePlacement: "ai", // left | center | top | bottom | ai
  visualPlacement: "ai", // right | left | center | full_bg | corner | ai
  textSafeArea: "normal", // wide | normal | minimal
  logoMode: "none", // none | org_text | logo_space | logo_and_org
  logoPlacement: "ai", // top_left | top_right | bottom_left | bottom_right | footer_bar | ai
  infoDensity: "standard" // minimal | standard | detailed
}
```

현재의 평면 상태값(`coverTitle`, `coverSubtitle`, `coverMeta`)은 MVP에서는 유지할 수 있지만, 고도화 단계에서는 `state.cover.*` 구조로 옮기는 편이 좋다.

### 7A.5 표지 프롬프트 반영 정책

표지 프롬프트는 아래 블록을 추가로 가진다.

```text
[Cover Content]
- Cover title
- Cover subtitle
- Date/version
- Presenter/author
- Department/event/course
- Organization
- Logo placeholder rules

[Cover Strategy]
- Emphasis mode
- Title placement
- Main visual placement
- Text safe area
- Information density
```

강조 방식별 프롬프트 변화:

- 텍스트 중심
  - 제목이 가장 큰 시각 요소가 되도록 지시.
  - 비주얼은 저대비 배경, 선, 패턴, 추상 오브젝트로 제한.
- 비주얼 중심
  - 메인 오브젝트를 강하게 배치.
  - 제목은 비주얼과 겹치지 않는 명확한 안전 영역에 배치.
- 균형형
  - 제목과 비주얼의 비중을 균형 있게 배치.
  - 기본값.
- 로고/기관 신뢰 중심
  - 기관명/로고 자리/공식 문서 톤을 강조.
  - 장식보다 정렬, 여백, 신뢰감을 우선.

### 7A.6 구현 단계

1. HTML 확장
   - 표지 전용 패널에 `발표일`, `발표자`, `부서/행사명` 입력 추가.
   - `표지 설계 전략` 컨트롤 추가.
   - 라디오/segmented button 중심으로 구성해 초보 사용자가 직접 문장을 쓰지 않아도 선택 가능하게 한다.

2. CSS 정리
   - 표지 패널 안을 `표지에 들어갈 정보`와 `표지 설계 전략` 두 하위 카드로 나눈다.
   - 컨트롤은 2열 그리드, 모바일은 1열.
   - 로고 설정은 로고 사용 여부가 `none`이 아닐 때만 배치 선택을 강조한다.

3. JS 상태 확장
   - `syncStateFromInputs()`에 표지 전용 입력 추가.
   - `resetAll()`에 기본값 추가.
   - 표지 선택 시 표지 전용 패널 표시.
   - `textModeInstruction("cover")`가 표지 전용 텍스트를 우선 사용하도록 수정.

4. 프롬프트 엔진 확장
   - `targetSpecificContext("cover")`에 표지 콘텐츠와 전략을 반영.
   - `targetRules("cover")`에 강조 방식, 제목 배치, 로고 자리, 정보 밀도 지시 추가.
   - `AI 위임` 선택지는 고정 배치값 대신 “제목 길이와 비주얼 구조에 맞춰 최적 배치를 선택”하도록 작성.

5. 검증
   - 표지 모드에서 각 입력값이 프롬프트에 들어가는지 확인.
   - 강조 방식별로 프롬프트 문장이 달라지는지 확인.
   - 로고 자리 없음/로고 자리 확보 옵션이 프롬프트에 다르게 반영되는지 확인.
   - 모바일에서 표지 패널이 너무 길어지지 않는지 확인.

## 7B. 간지 입력 구조 고도화 계획

간지는 표지처럼 많은 정보를 담는 장이 아니라, 문서의 흐름을 끊고 다음 장의 성격을 알려주는 전환 장치다. 따라서 간지의 핵심은 `섹션 인식`, `문서 전체 스타일과의 연결`, `다음 내용을 읽을 준비`이다.

### 7B.1 간지 전용 입력 항목

- 장 번호
  - 예: `01`, `PART 1`, `Chapter 03`
  - 가장 강한 식별자 또는 보조 식별자로 사용한다.
- 섹션 제목
  - 예: `사업 추진 개요`
  - 간지의 핵심 텍스트다.
- 섹션 설명
  - 예: `주요 목표와 추진 체계를 정리합니다`
  - 선택 입력. 너무 길면 작은 보조 문구로만 처리한다.
- 다음 장 키워드
  - 예: `성과`, `전략`, `일정`, `예산`, `실행계획`
  - 비주얼 메타포나 장식 패턴을 정하는 데 사용한다.
- 구분 강도
  - `강하게`
    - 큰 장 번호, 명확한 구획, 강한 여백 대비.
  - `보통`
    - 기본값. 제목 중심과 장식 균형.
  - `은은하게`
    - 배경에 가까운 부드러운 전환.
- 섹션 번호 표시 방식
  - `크게`
  - `작게`
  - `없음`
  - `AI 위임`
- 간지 레이아웃
  - `좌측 제목형`
  - `중앙 제목형`
  - `상단 바형`
  - `대각선 분할형`
  - `AI 위임`

### 7B.2 간지 프롬프트 반영 정책

간지 프롬프트에는 아래 블록을 추가한다.

```text
[Divider Content]
- Section number
- Section title
- Section description
- Next section keywords

[Divider Strategy]
- Transition strength
- Section number treatment
- Divider layout
```

간지는 표지보다 비주얼 강도를 낮춘다. 메인 비주얼이 있더라도 섹션 제목을 압도하지 않도록 한다.

  - `오른쪽 본문 공간 비우기`
  - `상단 제목 공간 비우기`
  - `하단 캡션 공간 비우기`

  - `밝게`

### 7C.2 배경 프롬프트 반영 정책

## 7D. 안내판 입력 구조 고도화 계획

안내판은 목적에 따라 입력 구조가 가장 크게 달라진다. `위치/장소 안내`, `방향 안내`, `절차 안내`, `일정/프로그램 안내`, `주의/공지`는 서로 다른 정보 구조를 가진다. 따라서 안내판은 하나의 공통 textarea로 처리하지 않고, 목적별 입력 패널을 제공한다.

### 7D.1 안내판 목적 구분

- 위치/장소 안내
  - 특정 장소, 층, 방, 접수처, 부스 등을 알려준다.
- 방향 안내
  - 왼쪽/오른쪽/직진/위층/아래층처럼 이동 방향을 알려준다.
- 절차 안내
  - 접수, 대기, 상담, 제출, 확인 등 단계 순서를 알려준다.
- 일정/프로그램 안내
  - 시간표, 세션, 장소, 발표자, 순서를 알려준다.
- 주의/공지
  - 금지, 유의사항, 운영 정책, 안전 안내, 긴급 공지를 전달한다.

### 7D.2 안내판 공통 입력 항목

- 안내판 제목
  - 예: `접수처 안내`, `세미나실 이동 안내`, `촬영 금지 안내`
- 보조 문구
  - 예: `아래 안내에 따라 이동해 주세요`
- 정보 위계
  - `제목 크게`
  - `정보 블록 중심`
  - `아이콘 중심`
  - `방향 화살표 중심`
- 아이콘 사용 여부
- 로고 자리 확보 여부
- QR 자리 확보 여부
- 멀리서 읽기 우선
  - 체크 시 대비, 글자 크기, 정보 블록 간격을 강화한다.

### 7D.3 위치/장소 안내 입력

- 장소명
  - 예: `접수처`, `운영데스크`, `세미나실 A`
- 층/구역
  - 예: `2층`, `B구역`, `로비 오른쪽`
- 주변 기준점
  - 예: `엘리베이터 옆`, `안내데스크 뒤편`
- 운영 시간
  - 예: `09:00-18:00`
- 문의처/담당
  - 예: `운영본부`, `현장 스태프`
- 표시 구조
  - `장소명 크게 + 보조 위치`
  - `장소 카드 3개`
  - `층/구역 중심`

### 7D.4 방향 안내 입력

- 목적지
  - 예: `세미나실`, `전시장`, `등록 데스크`
- 방향
  - `왼쪽`
  - `오른쪽`
  - `직진`
  - `위층`
  - `아래층`
  - `AI 위임`
- 거리/소요 시간
  - 예: `50m`, `도보 2분`
- 방향 보조 문구
  - 예: `화살표를 따라 이동해 주세요`
- 화살표 강조 정도
  - `강하게`
  - `보통`
  - `작게`

### 7D.5 절차 안내 입력

- 절차 제목
  - 예: `참가 등록 절차`
- 단계 수
  - `3단계`
  - `4단계`
  - `5단계`
- 단계별 내용
  - 예: `1. 접수 확인 / 2. 명찰 수령 / 3. 세션 입장`
- 완료 후 안내
  - 예: `문의는 운영데스크로 방문해 주세요`
- 절차 표시 방식
  - `가로 단계형`
  - `세로 단계형`
  - `번호 카드형`
  - `아이콘 단계형`

### 7D.6 일정/프로그램 안내 입력

- 프로그램명
  - 예: `성과공유회 세부 일정`
- 날짜
  - 예: `2026.07.05`
- 시간표 항목
  - 예: `10:00 개회 / 10:30 발표 / 12:00 네트워킹`
- 장소
  - 예: `컨퍼런스룸 A`
- 발표자/진행자
  - 예: `김OO 센터장`
- 표시 방식
  - `시간표형`
  - `세션 카드형`
  - `상단 날짜 + 하단 리스트`

### 7D.7 주의/공지 입력

- 공지 유형
  - `주의`
  - `금지`
  - `필수 안내`
  - `긴급 공지`
  - `운영 안내`
- 핵심 문장
  - 예: `행사장 내 촬영은 제한됩니다`
- 세부 안내
  - 예: `사전 승인된 인원만 촬영할 수 있습니다`
- 강조 수준
  - `강함`
  - `보통`
  - `부드럽게`
- 아이콘 성격
  - `주의 아이콘`
  - `금지 아이콘`
  - `정보 아이콘`
  - `아이콘 없음`
- 톤
  - `공식적`
  - `친절하게`
  - `긴급하게`
  - `차분하게`

주의/공지 안내판은 광고처럼 보이면 안 된다. 정보 전달, 판독성, 공적 신뢰감을 우선한다.

### 7D.8 안내판 프롬프트 반영 정책

안내판 프롬프트에는 목적별 블록을 추가한다.

```text
[Signboard Purpose]
- location / direction / process / schedule / notice

[Signboard Content]
- purpose-specific fields

[Signboard Structure]
- hierarchy
- icon usage
- arrow/block/step/list layout
- logo/QR placeholders

[Signboard Safety]
- do not invent details
- do not render fake maps unless explicitly requested
- keep text short and readable
```

목적별 프롬프트 차이:

- 위치/장소 안내
  - 장소명, 층/구역, 기준점을 정보 블록으로 구성한다.
- 방향 안내
  - 화살표와 목적지를 가장 크게 배치한다.
- 절차 안내
  - 단계 번호와 순서를 명확히 한다.
- 일정/프로그램 안내
  - 시간표 또는 세션 카드 구조를 우선한다.
- 주의/공지
  - 핵심 문장, 경고/정보 아이콘, 세부 안내를 위계화한다.

## 7E. 전체 양식 입력 구조 총괄

최종 입력 구조는 아래처럼 정리한다.

```text
[공통 정보]
- 프로젝트/문서명
```

구현 우선순위는 다음과 같다.

1. 표지 전용 설정 확장
2. 안내판 목적별 입력 패널 분리
3. 배경 편집 안전 영역/장식 설정 확장
4. 간지 전환 강도/번호 표시 설정 확장
5. 세트 모드에서 4개 패널이 너무 길어지지 않도록 접힘 UI 적용

### 7.2 표지 변환

표지는 비주얼 믹서 스타일을 가장 적극적으로 반영한다.

포함 지시:

- 큰 제목 영역
- 서브타이틀/기관명/날짜 자리
- 키비주얼 또는 상징 오브젝트
- 프리미엄 문서 표지 품질
- 중앙 또는 좌측 시선 흐름

금지 지시:

- 광고 배너처럼 과한 CTA
- 복잡한 본문 텍스트
- 제목 판독성을 해치는 배경

### 7.3 간지 변환

간지는 섹션 구분이 먼저 읽혀야 한다.

포함 지시:

- 장 번호 또는 섹션명 중심
- 표지와 같은 스타일 언어
- 중간 강도의 장식
- 넓은 여백

금지 지시:

- 표지보다 강한 키비주얼
- 지나치게 많은 오브젝트
- 본문 슬라이드처럼 보이는 복잡한 정보

### 7.4 배경 변환

배경은 후편집성과 가독성이 최우선이다.

포함 지시:

- 본문이 올라갈 중앙/주요 영역 비우기
- 낮은 대비의 패턴, 선, 질감
- 가장자리 중심의 장식
- 텍스트 없는 클린 배경

금지 지시:

- 실제 문장 생성
- 중앙을 가득 채우는 오브젝트
- 강한 명암 대비
- 포스터처럼 완성된 장면

### 7.5 안내판 변환

안내판은 정보 전달성과 시각적 위계를 우선한다.

포함 지시:

- 제목 영역
- 정보 블록 또는 방향 표시 영역
- 아이콘/화살표 자리
- 로고/QR 자리 선택적 확보
- 멀리서도 읽히는 대비
- 행사장, 회의장, 전시, 교육 공간에 어울리는 안내 그래픽

금지 지시:

- 실제 지도처럼 오해되는 허위 공간 구조
- 임의 세부 텍스트 과다 생성
- 장식이 정보 블록을 침범하는 구성
- 상업 광고 CTA처럼 보이는 과장된 표현

## 9. 이미지 생성 탭 전달

`양식 이미지`에서 생성한 프롬프트는 기존 `슬라이드 이미지 생성` 탭으로 전달할 수 있게 한다.

권장 방식:

- `window.getCurrentFormImagePrompt()` 제공
- `src/slide-image-generation.js`에서 마지막 활성 탭이 `tabBtnFormImage`이면 해당 프롬프트를 읽는다.
- `이미지 생성으로 보내기` 버튼은 `tabBtnSlideImage.click()` 후 입력 영역에 프롬프트를 채우는 기존 패턴을 재사용한다.

## 12. MVP 범위

첫 구현은 아래 범위로 제한한다.

- 새 탭 `양식 이미지` 추가
- 비주얼 믹서에서 `양식 이미지에 적용`
- 단일/세트 모드
- 표지/간지/배경/안내판 프롬프트 생성
- 세트 모드에서 4종 동시 생성
- 프롬프트 복사
- 이미지 생성 탭 전달
- 기존 `부속 양식` 탭은 변경하지 않음

2차 고도화 후보:

- 양식 이미지 전용 프리셋 라이브러리
- 분위기/용도 메모 기반 추천 스타일
- 안내판 레이아웃 썸네일 선택
- 세트 결과를 JSON으로 저장/불러오기
- 생성 결과 이미지와 프롬프트 히스토리 관리

## 13. 주요 리스크와 대응

### 기존 비주얼 믹서 UI 과밀

버튼이 많아질 수 있다. 결과 카드의 액션 버튼은 2열 그리드나 드롭다운으로 정리한다.

### 기존 부속 양식과 역할 혼동

탭 설명과 버튼명을 명확히 한다.

- `부속 양식`: 정형 문서 양식 프롬프트
- `양식 이미지`: 비주얼 믹서 기반 이미지 프롬프트

### 배경 프롬프트가 너무 화려해지는 문제

배경 변환 함수에 낮은 대비, 텍스트 없음, 중앙 여백 확보 지시를 강하게 넣는다.

### 안내판이 광고 이미지처럼 변하는 문제

안내판 변환 함수에 정보 블록, 방향성, 판독성, 공공 안내 그래픽 기준을 우선 적용한다.

### 탭 추가로 모바일 탭 바가 넘치는 문제

기존 `.app-tabs`의 가로 스크롤 정책을 유지하고, 버튼 텍스트를 짧게 `양식 이미지`로 제한한다.
