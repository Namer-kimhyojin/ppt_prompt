# PromptDeck AI 업무 도구 기능 구성·구현안

- 작성일: 2026-11-14
- 상태: 사용자 요청에 따라 제공 범위를 스킬·플러그인·MCP로 확장한 제안 문서
- 구현 상태: 구성안과 유튜브 조사에 근거한 초기 카탈로그 데이터를 작성. 공개 화면 연결·예약 작업 생성·스킬 설치·커밋·배포는 수행하지 않음.

## 1. 제공 목적과 범위

사용자가 자신의 업무에 맞는 AI 확장 도구를 찾고, 사용환경에 맞춰 설치하거나 연결하고, 첫 결과물을 확인하며, 이후 변경사항을 계속 확인하도록 한다.

메뉴 이름은 **AI 업무 도구**, 설명은 **업무에 바로 쓰는 스킬·플러그인·MCP**로 한다. 세 유형은 첫 출시부터 모두 지원한다.

| 유형 | 사용자에게 설명하는 역할 | 제공 동작 |
| --- | --- | --- |
| 스킬 | AI가 특정 업무를 수행하는 절차와 참고자료 | 공식 설치 안내, 배포 가능한 패키지 다운로드, 등록·호출 예제 |
| 플러그인 | 스킬·도구 연결 등을 설치 단위로 묶은 확장 기능 | 공식 설치 페이지, 활성화·연결 안내, 포함 기능과 사용 예제 |
| MCP | AI와 외부 자료·프로그램을 연결하는 방식이며, 카탈로그에는 MCP 서버·서비스를 등록 | 실행환경별 연결 안내, 설정 예제 복사, 연결·업무 수행 확인 |

실제로 제공 가능한 동작에 맞춰 버튼을 표시한다. 원격 MCP는 연결 안내를, 로컬 MCP는 설치·실행 안내를 제공한다. 다운로드한 파일, 설치된 도구, 연결된 서비스, 실제 업무 수행 성공을 구분한다.

이번 허브는 소개·큐레이션·설치/연결 지원을 담당한다. 외부 MCP를 PromptDeck 서버에서 직접 실행·중계하는 서비스는 별도 구현 범위다.

## 2. 정보 구조와 페이지

| 페이지 | 경로 제안 | 내용 |
| --- | --- | --- |
| 통합 목록 | /ai-tools/ | 추천, 업무 검색, 유형·사용환경 필터, 최근 갱신 |
| 상세 안내 | /ai-tools/{slug}/ | 소개, 설치·연결, 사용 예제, 확인 기록, 변경 이력 |
| 처음 시작하기 | /ai-tools/start/ | 세 유형의 차이, 환경 선택, 첫 설치·연결·실행 |
| 업무별 활용법 | /ai-tools/workflows/ | 한 업무에 필요한 도구와 적용 순서 |
| 업데이트 소식 | /ai-tools/updates/ | 신규 소개, 변경, 재설정 필요, 제공 중단·대체 안내 |

start, workflows, updates는 예약 slug로 사용한다. 기존에 제안했던 /skills/ 대신 /ai-tools/를 사용한다. 아직 공개하지 않은 /skills/에 대한 이전 처리는 필요하지 않다.

기존 공개 메뉴의 ‘스킬 다운로드’를 ‘AI 업무 도구’로 변경한다. 앱 헤더와 관련 작업 화면에도 링크를 추가한다. 기존 /guides/ppt-slide-planner-skill 및 ZIP 주소는 유지하거나 새 상세 페이지로 명시적으로 연결한다.

## 3. 검색과 추천

- 업무 분류: 문서·보고서 / 발표·제안서 / 엑셀·데이터 / 조사·자료 정리 / 홍보·디자인 / 반복업무·서비스 연결.
- 유형 필터: 전체 / 스킬 / 플러그인 / MCP.
- 사용환경 필터: 각 항목에서 확인한 호스트 앱·서비스를 기준으로 제공한다. 환경 목록은 데이터에서 생성한다.
- 부가 필터: 사용 확인 여부, 비용 조건, 설치 난이도. 기본 화면에서는 접어둘 수 있다.
- 정렬: 추천순 / 최근 소개 / 최근 안내 수정. 단순 링크 점검은 최근 업데이트 순위에 반영하지 않는다.
- 검색 대상: 업무명, 결과물, 도구명, 별칭, 연결 서비스, 태그.
- 검색·필터 조건은 URL 쿼리에 저장해 공유와 뒤로가기를 지원한다.

카드는 도구명보다 업무 결과를 먼저 보여준다. 예: ‘회의 자료를 정리해 후속 업무 목록 만들기’. 카드에는 도구명, 유형, 실제 확인한 사용환경, 준비물, 비용 조건, 확인 상태, 상세 안내 버튼을 둔다.

좋은 도구의 기준은 업무 결과의 명확성, 재현 가능성, 한국어 품질, 설치 부담, 유지관리 상태다. 인기 지표를 제공한다면 지표 이름과 조회일을 함께 적는다.

## 4. 상세 안내

공통 순서는 다음과 같다.

1. 해결할 업무와 예상 결과물, 적합한 사용자.
2. 필요한 자료·계정·프로그램·비용 조건.
3. 실제 사용환경 선택.
4. 선택한 환경에 맞는 설치 또는 연결 순서.
5. 첫 요청문과 샘플 입력·결과.
6. 등록·연결 확인과 실제 업무 수행 확인.
7. 자주 발생하는 문제와 해결 방법.
8. 관련 PromptDeck 기능과 업무별 활용법.
9. 제작자·공식 출처·배포 조건·변경 이력.

| 유형 | 전용 안내 항목 | 주요 버튼 |
| --- | --- | --- |
| 스킬 | 등록 위치 또는 등록 화면, 호출명, 포함 자료, 갱신 방법 | 설치 안내 / 예시 요청 복사 / 공식 출처 |
| 플러그인 | 대상 플랫폼, 배포처, 포함 스킬·연결 도구, 활성화, 추가 로그인 | 공식 설치 페이지 / 시작 안내 / 예시 요청 복사 |
| MCP | 로컬·원격 구분, 서버 준비, 대상 클라이언트, 연결 주소 또는 실행 명령, 인증, 제공 기능 | 연결 안내 / 설정 예제 복사 / 공식 출처 |

플랫폼이 다른 설정은 별도 탭이나 선택기로 제공한다. MCP 설정 예제는 지원 클라이언트와 적용 버전을 명시하고 비밀값 대신 자리표시자를 사용한다. 실제 인증정보는 사용자의 해당 앱·실행환경에 입력한다.

데스크톱은 본문과 목차를 함께 제공하고 모바일은 한 열로 배치한다. 핵심 동작은 최대 3개를 기본 노출한다. 지원하지 않는 원클릭 설치·연결을 암시하는 버튼은 만들지 않는다.

## 5. 포함 관계와 중복 방지

플러그인은 스킬과 MCP 구성을 함께 포함할 수 있다. 다음 관계를 구분한다.

- 포함: 플러그인을 설치할 때 함께 제공되는 구성요소.
- 필요: 사용 전에 별도 준비해야 하는 프로그램·계정·다른 도구.
- 함께 사용: 업무 흐름에서 선택적으로 조합할 수 있는 도구.

예를 들어 플러그인 카드에는 ‘스킬 2개·MCP 연결 1개 포함’을 표시할 수 있다. 포함된 기능을 사용하기 위해 같은 스킬이나 MCP를 다시 설치하도록 안내하지 않는다.

같은 프로젝트의 여러 배포 방식은 하나의 대표 소개 아래에서 선택하게 한다. 독립 배포되는 구성요소는 별도 소개가 가능하지만 원본과 포함 관계를 연결한다. 유형 필터는 실제 별도 제공되는 설치·연결 단위를 기준으로 하고, 내부 포함 구성은 별도로 표시한다.

## 6. 업무별 활용법

도구 소개 외에 준비물 → 적용 순서 → 산출물 → 확인 방법으로 구성한 업무 안내를 제공한다.

예시 설계: ‘여러 자료를 모아 보고서 작성하기’에서 자료 접근용 MCP, 내용 정리 스킬, 문서 작성 플러그인이 각각 어느 단계에 필요한지 설명한다. 이는 조합 안내의 예시이며 특정 제품 간 연동 검증을 의미하지 않는다.

각 안내는 필수·선택 도구를 구분하고, 이미 플러그인에 포함된 기능은 중복 설치하지 않도록 설명한다. 실제 호환 조합을 확인한 경우에만 해당 환경과 확인일을 표시한다.

## 7. 지속 업데이트 운영

기본 흐름: 공식 출처 점검 → 변경 후보 생성 → 사용법·예제 확인 → 공개 콘텐츠 개정 → 업데이트 소식·피드 반영.

| 주기 제안 | 작업 |
| --- | --- |
| 매일 | 등록 출처의 릴리스·해당 폴더 변경·링크 오류·이전 여부 점검 |
| 매주 | 변경 후보 검토, 신규 추천 선정, 안내와 예제 개정·발행 |
| 매월 | 오래된 검증 기록 재점검, 유지관리 중단 도구와 대체 후보 정리 |

신규 후보 발굴에는 유튜브의 공개 설명·챕터와 확보 가능한 제작자 전사를 활용한다. 영상 ID와 채널을 기준으로 중복을 제거하고, 같은 도구를 명시적으로 다루는 서로 다른 채널이 있는지 확인한다. 제작사 소개·협찬 표시·게시일 미확인은 별도로 기록한다. 영상의 설치 명령을 바로 공개 안내로 복사하지 않고 최신 공식 배포처와 대조한다.

유형별 감지 대상은 스킬의 지침·참고자료·스크립트, 플러그인의 매니페스트·포함 구성·설치법, MCP의 연결 주소·인증법·설정·제공 기능이다. 포함 구성요소가 변경되면 해당 플러그인과 관련 업무 안내도 점검 대상으로 올린다.

원본 변경일, 안내 수정일, 출처 확인일, 실행 확인일을 분리한다. 실행 확인 기록에는 대상 환경과 도구 버전, 설치/연결 성공, 대표 업무 수행 결과를 저장한다. HTTP 응답 성공이나 도구 목록 조회 성공만으로 업무 수행 완료를 표시하지 않는다.

콘텐츠 상태는 초안 / 게시 / 점검 필요로 단순하게 관리한다. 사용자에게는 소개 자료 / 사용 확인 / 재확인 필요 / 제공 중단을 실제 근거에 따라 표시한다. 출처 수집이 실패하면 기존 공개 안내와 확인일을 보존하고 검토 목록에 오류를 남긴다.

변경 글은 ‘달라진 점 / 영향받는 사용자 / 필요한 조치’를 포함한다. 예약 점검은 공개 자료 확인과 초안 작성까지만 자동화하고, 사용 확인 표시는 실제 확인 결과로 갱신한다.

## 8. 데이터와 구현 구조

| 구분 | 주요 정보 |
| --- | --- |
| 공통 | id, slug, 이름, 업무 결과, 업무 분류, 제작자, 출처, 라이선스, 비용 조건 |
| 제공 방식 | 유형, 공식 설치·연결 URL, 직접 배포 파일, 대상 환경, 버전, 설치·연결 단계 |
| 관계 | 포함 구성, 필수 의존 항목, 관련 도구, 관련 업무 안내 |
| 사용 안내 | 준비물, 첫 요청문, 샘플 결과, 성공 확인, 문제 해결 |
| 확인 기록 | 출처 확인, 실제 환경별 설치·연결·업무 수행 결과와 날짜 |
| 변경 이력 | 원본 변경일, 안내 수정일, 변경 요약, 사용자 조치, 검토 상태 |
| 추천 근거 | 영상 ID·URL·채널·게시일, 설명/챕터/전사 구분, 언급 요약, 확인 가능한 타임스탬프, 표본 내 채널 수 |

MCP 전용 정보에는 로컬·원격 방식, 클라이언트별 설정, 인증 유형, 계정·권한 조건, 제공 기능을 둔다. 플러그인 전용 정보에는 플랫폼·배포처·포함 구성요소를 둔다. 스킬 전용 정보에는 호출·등록 방식과 포함 참고자료를 둔다.

제안 파일 구조:

```text
content/ai-tools/{slug}.json
content/ai-tools/guides/{slug}.md
content/ai-workflows/{slug}.md
scripts/build-ai-tools.mjs
scripts/check-ai-tool-sources.mjs
static-pages/ai-tools/                 # 화면 템플릿
src/ai-tools-catalog.js
styles/ai-tools.css
```

콘텐츠 원본과 템플릿에서 목록·상세·변경 소식·검색 인덱스를 생성한다. 생성 HTML은 배포 결과물에 작성하고 원본과 수작업으로 이중 관리하지 않는다. 생성 결과를 기존 sitemap과 feed에 병합해 기존 가이드 항목도 유지한다.

현재 코드 연결 지점:

- src/public-nav.js: 공개 메뉴 링크와 현재 페이지 표시 변경. 공개 페이지의 기본 HTML 내비게이션도 함께 갱신.
- index.html: 작업 도구에서 허브로 이동하는 진입 링크.
- scripts/build-static.mjs: 신규 생성 단계·배포 경로·사이트맵·피드 연계.
- server/local-server.js: 로컬 개발에서 신규 주소와 정적 자산 연결.
- static-pages/guides/ppt-slide-planner-skill.html: 기존 가이드·배포 링크 보존 및 신규 소개와 연결.

첫 버전은 현재 정적 사이트 구조와 Codex 편집으로 운영한다. 기존 관리자 설정 API는 콘텐츠 CMS가 아니므로 후속 관리자 편집 기능은 별도 콘텐츠 저장·공개 경계를 설계한다.

## 9. 출시 범위와 확인 항목

첫 출시부터 스킬·플러그인·MCP 세 유형을 제공한다. 초기 콘텐츠는 총 12~18개를 목표로 하되, 유형별 4~6개는 편집 목표이며 검토 없이 수량을 채우지 않는다. 기존 ppt-slide-planner 안내도 현재 설치법·패키지 기준을 확인한 후 포함한다.

필수 기능은 통합 목록, 유형·업무·환경 필터, 유형별 상세 안내, 처음 시작하기, 업무별 활용 예시, 업데이트 소식, 변경 감지와 검토 목록이다. 이후 관심 항목 저장, 비교, 관리자 편집을 확장한다.

출시 전 확인:

- 세 유형 각각 검색·필터·상세 이동·뒤로가기·빈 결과 안내가 작동한다.
- 환경을 바꾸면 설치·연결 안내와 복사 예제가 해당 환경에 맞게 바뀐다.
- 플러그인 포함 관계와 독립 배포 여부가 올바르게 표시된다.
- MCP의 연결 성공과 업무 수행 확인이 별도로 표시된다.
- 실제 검증하지 않은 항목에는 사용 확인 표시가 없다.
- 변경 수집 성공·실패·원본 이전·포함 항목 변경을 구분한다.
- 기존 가이드·다운로드 주소, 모바일 레이아웃, 키보드 탐색, 사이트맵·피드가 유지된다.

성과는 검색 후 상세 열람, 예시 복사, 공식 설치·연결 안내 클릭, 관련 업무 안내 이동으로 측정한다. 클릭만으로 설치 성공이나 업무 완료를 추정하지 않는다.
