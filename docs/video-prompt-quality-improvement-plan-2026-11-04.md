2026-11-14 진행 상태: 아래 계획은 11월 4일 조사 기록이다. 이후 추가된 로컬 상세 사양 연동 코드를 이어서 1차 구현을 보완했다. 현재는 기획·제작 요청문 모두에 66개 스타일의 상세 사양과 18개 용도별 연출 지침·구성 의도가 전달된다. 로딩 실패·잘못된 버전에는 요청문 복사와 저장을 막고 명시적인 다시 불러오기를 제공한다. 사용자 조건을 스타일보다 우선하고 음성·음악·효과음의 개별 없음/원본 활용 설정을 적용한다. 한국어 내레이션의 화자 미지정 기본값은 Supertonic 3 M1이며, 지정 화자와 제공 녹음을 우선한다. 외부 AI의 실제 영상 생성 품질 비교와 배포는 이번 구현 범위에 포함하지 않았다.

1차 구현에서는 화면용 정보와 생성용 정보를 분리한다. 카드에는 기존의 짧은 `visual`·`motion` 소개를 사용하고, 생성기는 별도의 상세 규칙을 사용한다. 제안하는 데이터는 `원문·출처·버전`, `화면·재질`, `색상`, `문자 배치`, `움직임`, `카메라`, `전환`, `음향`, `고유 연출`, `피할 표현`이다. 검증용으로 각 스타일의 필수 규칙과 적용 조건도 기록한다.

원문은 가져오기 단계에서 저장하고 검수한다. 실행 중 외부 링크를 읽어 오도록 만들지 않는다. 따라서 오프라인에서도 동일한 요청문을 만들 수 있고, 외부 원문의 변경이 사용자 결과를 갑자기 바꾸지 않는다. 원본 해시 확인은 출처 동일성 검사이며, 상세 규칙이 적절히 반영됐는지는 별도로 대조한다.

최종 요청문의 조합 순서는 `사용자가 확정한 내용 → 영상 용도별 지침 → 선택한 스타일의 상세 규칙 → 원하는 산출물`로 한다. AI 추천을 선택한 경우에는 현재처럼 스타일 3안을 비교하고 1안을 추천하게 한다. 스타일을 직접 선택한 경우에는 해당 스타일의 기획안 1개를 요청한다.

규칙 충돌은 다음 기준으로 해결한다.

1. 사용자가 제공한 사실·문구·원본 형태와 명시적으로 선택한 조건을 우선한다.
2. 용도별 사실 보존 규칙을 적용한다. 데이터의 단위·비교 기간, 지도의 위치 관계, 앱의 실제 기능이 스타일 때문에 변하지 않게 한다.
3. 그 범위 안에서 스타일의 상세 규칙을 적용한다. 사용자가 무음을 선택했다면 스타일에 있는 음악·음성 권장은 적용하지 않는다.
4. 원문의 예시 줄거리·등장인물·고정 영상 길이·특정 코드 환경을 사용자의 기획 조건으로 옮기지 않는다. 실물 제품을 제공한 경우 원문의 가상 제품 예시가 실물 보존 조건을 덮어쓰지 않게 한다.
5. 상세 규칙이 등록되지 않은 스타일은 결과 화면에 누락 사실을 표시하고 개발 검증에서 실패시킨다. 상세 지침이 반영된 것으로 표시하지 않는다.

`beats`는 이야기에서 다룰 내용의 참고 방향으로 사용한다. 세 항목이 있다고 반드시 세 장면을 만들거나 각 장면을 5초로 고정하지 않는다. 사용자가 정한 영상 길이 안에서 장면 수와 순서를 AI가 결정하도록 유지한다.

현재 기본 요청문은 291자이며, 테스트는 기본 상태에 대해 500자 미만을 요구한다. 이 기본 상태의 간결성은 유지한다. 선택한 스타일의 상세 프롬프트는 별도 길이 기준으로 검증하고, 단순히 글자 수를 줄이기 위해 고유 규칙을 삭제하지 않는다. 화면에는 상세 규칙을 접어 표시하되 복사·TXT 본문에는 적용 대상 규칙을 모두 포함한다.

예를 들어 스위스 모션 선택 시 다음 정도의 구체성이 실제 요청문에 들어가야 한다. 아래 문장은 구현 후 출력 방향을 보여 주는 예시이며 현재 출력은 아니다.

> 화면 전체를 일관된 격자로 정렬하고 강조색은 한 가지로 제한한다. 요소는 격자 위치에 정확히 도착하며 튀거나 탄성 있게 흔들리지 않는다. 문구는 마스크를 통해 등장하고, 전환은 절단·이동·재배치 방식으로 연결한다. 무음이면 시각적 박자로 움직임을 조직한다. 사용자가 제공한 문구와 수치는 유지한다.

2차에서는 AI가 작성할 기획안의 구체성을 높인다. 각 장면에 `시간 / 전달할 내용 / 시작 화면과 끝 화면 / 주요 동작 / 자막 / 음성·음향 / 필요한 에셋`이 연결되도록 요청한다. 화면 변화는 “역동적으로” 같은 형용사에 그치지 않고 대상·방향·변화 결과로 설명하게 한다. 카메라 이동은 필요한 장면에만 제안하도록 한다. 주체·행동·카메라를 구분하는 방향은 [Google 영상 프롬프트 가이드](https://cloud.google.com/vertex-ai/generative-ai/docs/video/video-gen-prompt-guide)를 참고한 설계 제안이며, 특정 영상 모델 연결을 전제로 하지 않는다.

길이가 지정되면 장면 시간의 합이 그 길이에 맞도록 요청하고, 길이가 AI 추천이면 전체 길이와 장면표가 일치하도록 한다. 원본 음성의 길이나 실제 읽기 시간이 확인되지 않으면 추정이라고 표시한다. 근거 없는 고정 글자 수를 모든 내레이션의 적합 기준으로 사용하지 않는다.

원문과 추가 요구사항은 평문 영역을 구분하여 전달한다. 복사된 원문 속 지시 문장이 사용자의 선택 조건을 임의로 덮어쓰지 않게 하고, 지정된 사실과 창작 가능한 부분을 구별한다. 명확한 출력 요구와 맥락 구분은 [Anthropic 프롬프트 가이드](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)를 참고하되, 현재 제품의 태그 없는 요청문 형식에 맞게 적용한다.

| 스타일·참조 이미지가 모두 없어도 “첨부한 화풍 기준 이미지”라고 출력 | 참조 없음·화풍 참조·대상 참조를 구분한다. 참조가 없으면 사용자의 설명을 기준으로 생성하며 기준 이미지를 확보할 필요가 있는 경우 안내한다. |
| 대상 참조가 없어도 “첨부한 대상 원본의 정체성 유지”라고 출력 | 기존 대상 보존과 신규 대상 설계를 입력 상태에 따라 구분한다. |
| 기본 색상·조명이 모든 스타일에 들어감 | 사용자 지정값과 초기 기본값을 구분한다. 지정하지 않은 값은 선택한 스타일과 조화되도록 위임하고, 기존 저장값은 마이그레이션에서 보존한다. |
| “핵심 구역 1·2·3”, “주요 부품 1·2” 등 추상적인 개별 파일 설명 | 공간·부품·사용 상태의 실제 이름을 간단히 입력하거나 확인할 수 있게 한다. 각 파일에 해당 항목의 설명을 전달한다. |
| 제공 에셋만 사용을 골라도 용도에 따라 자료 누락 안내가 없음 | 에셋 활용 방식에 따른 누락 검사를 추가한다. 파일명을 적은 사실과 실제 파일 첨부 여부는 구분한다. |

기존 패럴랙스 규칙인 전체 전경 기준, 동일 캔버스·카메라·원점·소실점, 레이어 재중앙화 금지는 유지한다. 투명 PNG·목표 해상도는 요청 조건이며 실제 생성 파일의 속성을 보장하는 것으로 표시하지 않는다. 실제 파일을 평가할 때 알파 채널·크기·합성 정합을 따로 확인한다.

모션 기획과 영상 에셋의 연결은 1차 이후로 둔다. 우선 영상 제목·세계관·화면비·시각적 스타일·고정 요소를 가져오는 작은 동작부터 검토한다. 서로 다른 스타일 카탈로그의 ID를 그대로 복사하지 않고 영상 스타일의 시각 규칙만 옮긴다. 움직임 지시나 배경음악이 정지 이미지 요청문으로 섞이지 않게 한다. 기존 입력을 덮어쓸 때는 적용 범위와 되돌리기를 제공한다.

구현 파일별 책임은 다음과 같이 나눈다. 아래 신규 파일명은 계획안이다.

검증은 텍스트 전달의 정확성과 외부 AI가 만든 결과의 품질을 분리한다.

1. **전수 전달 검사:** 66개 스타일의 필수 규칙과 18개 용도의 적용 지침이 출력되는지 확인한다. 이름만 들어가는 검사는 충분하지 않다. 서로 다른 스타일의 규칙이 섞이지 않는지도 확인한다.
2. **조건 조합 검사:** 스타일 지정/AI 추천, 무음/음성/원본 음원, 제공 자료만/생성/혼합, 길이 지정/추천, 참조 없음/있음, 기존 저장자료를 포함한다. 무음과 스타일 음악 권장이 충돌하면 무음 조건을 유지해야 한다.
3. **실제 사용 검사:** 데스크톱·모바일에서 선택 변경, 앞/뒤 단계, 복사, TXT 저장, 새로고침, 되돌리기를 확인한다. 탭 공통 영역을 수정하면 지도·부속 양식 탭과 액션 도크도 확인한다.
4. **기획 품질 비교:** 기존 샘플 중 모집 안내·제품 소개·데이터 성과·앱 시연·안전교육·브랜드 소개 6건을 사용한다. 같은 모델·설정에서 기존/개선 요청문을 각각 2회 실행해 비교하고 모델명·버전·실행일을 기록한다. 필요하면 다른 모델에서도 같은 비교를 한다.
5. **이미지 품질 비교:** 합성용 인물, 제품, 쇼츠 배경, 패럴랙스 묶음을 대표 사례로 삼는다. 기준 대상 보존, 잘림, 여백, 투명도, 레이어 정합을 실제 이미지에서 확인한다.

실제 AI 비교에서는 사실 보존·스타일 구현·장면 구체성·시간/음향 적합성·제작 가능성을 각각 1~5점으로 평가한다. 템플릿별 필수 규칙과 사용자가 확정한 사실의 위반은 평균 점수와 별도로 기록한다. 초기 채택 기준안은 필수 전달 검증 전부 통과, 대표 결과에 중대한 조건 위반 없음, 기존 대비 개선 선호 비율 75% 이상이다. 이 수치는 앞으로 확인할 목표이며 현재 달성한 결과가 아니다. 작은 표본의 결과를 전체 모델·모든 영상 품질로 일반화하지 않는다. 측정 기준과 이전 버전 비교를 먼저 정하는 방식은 [Anthropic 평가 가이드](https://platform.claude.com/docs/en/test-and-evaluate/develop-tests)를 참고했다.

이번 조사에서는 생성 함수를 직접 호출해 용도별 지침 누락, 상세 스타일 데이터 부재, 없는 참조를 전제하는 문구를 재현했다. `node scripts/motion-prompt-test.mjs`와 `node scripts/video-assets-test.mjs`가 모두 통과했다. 데스크톱 결과 화면과 모바일 스타일 화면도 확인했으며, 영상 에셋 검증은 1440×1000·1280×720·390×844·375×667·844×390에서 통과했다. 기존 테스트 통과는 현재 동작의 회귀 기준이고 상세 템플릿 반영이나 외부 AI 결과 품질의 확인을 뜻하지 않는다.

구현 시 변경한 JavaScript의 `node --check`, `git diff --check`, 두 영상 전용 검증을 실행한다. 탭·공통 UI를 수정하면 `node scripts/smoke-test.mjs`와 데스크톱·모바일 클릭 검증을 추가한다. UTF-8 without BOM과 한글 손상 여부를 확인하고 기존 미커밋 변경은 보존한다. 템플릿 연결 복구를 마친 다음에 장면 구성·에셋 개선을 이어간다.
