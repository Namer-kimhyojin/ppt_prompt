# 홍보용 이미지 탭 기능 점검 및 개선방향

점검일: 2026-09-04 · 대상: 현재 로컬 작업본 · 구현 변경 없이 점검·계획 수립

## 1. 종합 판단

기본 프롬프트 제작 기능은 충분히 구현되어 있다. 다음 개발에서는 기능 추가보다 **사용자가 편집·선택한 내용이 저장, 복사, 다음 탭 전달까지 일관되게 유지되는 것**을 먼저 보장해야 한다.

핵심 개선 순서는 **편집 데이터 보존 → 요약 창·규격·로고 오류 수정 → 모바일 입력 동선 → 추천·프롬프트 품질**이다. 실제 생성 이미지의 품질과 배포 상태는 이번 결과에 포함하지 않는다.

### 확인 범위와 방법

- 현재 `index.html`, `src/promotion*.js`, `styles/promotion.css`, 탭 액션 및 이미지 생성 탭 연결 코드를 확인했다.
- 로컬 HTTP 환경의 Edge에서 실제 화면과 동작을 점검했다. 데스크톱 1440×1000, 모바일 390×844 및 360×800을 사용했다.
- 일반 입력, 요약, 편집·복사, JSON 저장·복원, 브라우저 새로고침, 규격 프리셋, 화풍 추천, 레이아웃, 로고·QR, 모바일·다크 모드를 확인했다.
- 클릭·입력 중심으로 검증했고, 일부 숨긴 체크박스 및 설정 핸들러는 DOM 이벤트로 확인했다. 모든 컨트롤의 포인터 조작성을 전수 보장한 것은 아니다.
- `promotion-parser-test.mjs` 통과: 기관형 코퍼스 8개 및 라벨형·서술형·표형·근거·압축·빈 입력 검사.
- `promotion.js`, `promotion-prompt-engine.js`, `promotion-parser.js`, `promotion-data.js`, `promotion-utils.js`, `promotion-i18n.js` 문법 검사 통과.
- 관찰한 점검 브라우저의 JavaScript 실행 예외는 0건이다. 이는 아래 기능 결함이 없다는 뜻은 아니다.
- 전체 앱 smoke, 정적 빌드, 배포 검증, 실제 이미지 API 호출은 수행하지 않았다. 로컬 정적 서버에는 백엔드 API가 없으므로 서버 기능의 성공 여부를 판단하지 않았다.
- 기존 `index.html`·라벨 제작 관련 미커밋 변경은 보존했다. 소스 수정·커밋·푸시·배포는 하지 않았다.

## 3. 재현된 오류와 수정 방향

### F01 · P1 · 직접 편집본과 복사·전달 결과 불일치

- **재현:** 전체 편집에서 구분 문구 추가 → ‘미리보기’ → 전체 복사. 편집 textarea에는 문구가 남지만 뷰어와 클립보드에는 빠진다. 배지는 ‘직접 편집 중’으로 남기도 한다.
- **추가 재현:** 섹션 Edit → 문구 수정 → Save. 화면에는 수정 내용이 표시되지만 전체 복사에는 반영되지 않는다.
- **영향:** 화면에서 확인·저장한 결과와 외부 AI에 붙여넣는 결과가 달라진다. 반대로 이미지 생성 탭은 textarea의 편집본을 가져온다.
- **원인:** 전체 복사는 편집 모드에서만 textarea를 읽고 그 외에는 자동 프롬프트를 다시 생성한다. 섹션 Save는 편집 모드를 켜지 않는다.
- **방향:** ‘현재 유효한 프롬프트’를 하나로 정의해 뷰어·전체 복사·섹션 복사·저장·이미지 전달에 공통 사용한다. 자동 초안과 편집본을 별도로 유지하려면 명시적인 버전 선택 UI를 제공한다.
- **근거:** [현재 프롬프트 선택](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:5134>), [섹션 저장](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:5680>), [이미지 전달](<D:/00. Dev_Folder/Promptdeck/src/slide-image-generation.js:160>).

### F02 · P1 · 편집본의 저장·복원 결함

- **재현 A:** 직접 편집 → 설정 JSON 저장 → 같은 파일 불러오기. 파일에는 `promptDraft`와 `promptDirty`가 있지만 복원 후 편집 문구가 사라진다.
- **재현 B:** 섹션 Save 직후 새로고침. 섹션 변경이 브라우저 저장에 반영되지 않아 사라진다.
- **추가 위험:** 일반 입력 변경 핸들러는 `promptDirty=false`로 설정하므로 편집본을 자동 초안으로 교체한다. 편집 완료 후 설정을 조절하는 흐름을 보완해야 한다.
- **방향:** 파일 마이그레이션에서 편집본을 보존하고 섹션 저장도 동일한 저장 경로로 연결한다. 설정 변경 시 편집본을 유지하면서 ‘새 설정으로 초안 재생성’을 별도 선택하게 하고 실행 취소를 제공한다.
- **근거:** [파일 변환](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:5080>), [섹션 저장](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:5680>), [입력 변경](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:3424>).

### F03 · P1 · 원문 요약 창의 단계 숨김 실패

- **재현:** 원문 요약 창을 처음 열면 입력 영역과 분석 결과용 안내·압축·적용 버튼이 함께 표시된다. 결과 영역에는 `hidden` 속성이 있으나 실제로는 보인다.
- **원인:** `.promo-quickfill-modal-body { display:flex }`가 HTML 기본 숨김 스타일을 덮어쓰며, 단계별 `[hidden]` 보정이 없다.
- **영향:** 분석하기 전에 ‘선택 항목 적용’이 노출되고, 모바일에서 창이 불필요하게 길어진다. 기존 테스트의 `:not([hidden])` 확인만으로 실제 가시성 문제를 잡지 못한다.
- **방향:** 단계 숨김을 CSS에서 보장하고 현재 단계만 표시·탐색되도록 한다.
- **근거:** [단계 전환](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:2408>), [해당 CSS](<D:/00. Dev_Folder/Promptdeck/styles/promotion.css:452>).

### F04 · P1 · 사용자 지정 비율을 ‘내 규격’에서 복원하지 못함

- **재현:** 21:29.7 저장 → 사용자 지정 비율을 2:5로 변경 → 저장한 규격 적용. 결과가 21:29.7로 돌아오지 않고 2:5로 남는다.
- **원인:** 규격 스냅샷에 `ratio:custom`과 방향만 저장하고 `customRatioW/H`를 제외한다.
- **방향:** 실제 비율 숫자를 저장·복원하고 규격 목록에도 ‘21:29.7 세로’처럼 표시한다. 저장 시 숫자 유효성도 검사한다.
- **근거:** [규격 스냅샷](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:1129>).

### F05 · P2 · 로고 수동 배치와 출력 불일치

- **재현:** 주최 로고 2개, ‘그리드 배열’ 선택 → 프롬프트는 가로 일렬 지시를 출력한다.
- **원인:** 유효한 split이 아니면 총수 6개 이상은 grid, 그 미만은 row로 재결정한다. 사용자의 명시적인 grid 선택을 존중하지 않는다.
- **방향:** 수동 선택을 우선하고 자동 추천을 별도 모드로 분리한다. 자동 보정이 필요하면 변경 이유를 화면에 표시한다.
- **근거:** [배열 결정](<D:/00. Dev_Folder/Promptdeck/src/promotion-prompt-engine.js:1051>).

### F06 · P2 · 사용자 피드백 및 안내 불일치

- `status()`가 찾는 `#promotionStatus`가 현재 HTML에 없어 복사·저장·불러오기 실패 등의 메시지가 표시되지 않는다.
- 헤드라인이 없으면 ‘입력해야 복사할 수 있습니다’라고 안내하지만 실제로는 초안이 복사된다.
- 기관명은 ‘프롬프트에 넣지 않는다’고 안내하지만 `TEST_ORGANIZATION` 입력 시 `Organization list by role`에 그대로 포함된다. 이미지에 보이지 않도록 지시하는 것과 프롬프트에 포함하지 않는 것은 다른 동작이다.
- **방향:** 항상 보이는 상태 영역과 보조기기 알림을 연결한다. 미완성 초안 복사는 허용하되 ‘미완성 초안 복사’로 알리거나, 실제 차단 정책을 일관되게 적용한다. 기관명 설명은 ‘프롬프트에는 전달되며 이미지에 표시하지 않음’ 등 실제 정책과 일치시킨다.
- **근거:** [알림 함수](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:920>), [복사 조건 안내](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:2009>), [기관명 출력](<D:/00. Dev_Folder/Promptdeck/src/promotion-prompt-engine.js:1090>), [화면 안내](<D:/00. Dev_Folder/Promptdeck/index.html:1100>).

### F07 · P2 · 요약 선택 적용 후 비활성 항목은 최종 출력에서 누락

- **재현:** CTA 사용 끄기 → 원문 분석 → CTA를 선택해 적용. 값은 채워지지만 사용 상태는 꺼진 채여서 프롬프트에 나타나지 않는다. QR URL도 값 적용만으로 QR 사용이 켜지지는 않는다.
- **방향:** 적용 전에 ‘값만 저장 / 사용도 켜기’를 명확히 하거나, 선택 적용한 항목은 사용 상태까지 반영하고 변경 내역을 알려준다.
- **근거:** [선택 적용](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:3214>).

### F08 · P2 · 컨셉 재편집을 위한 선택 정보 소실

- **재현:** 랜덤 컨셉 적용 후 저장 상태에는 subject·medium·palette·composition·typography 식별자가 있으나 새로고침 후 모두 사라진다. 컨셉 설명 텍스트는 남는다.
- **원인:** 동적으로 추가한 식별자 필드가 기본 상태·정규화 대상에 없다.
- **방향:** 컨셉 식별자를 상태 스키마에 포함하고 새로고침·파일 재사용 후에도 같은 믹서 선택으로 돌아오도록 한다.
- **근거:** [상태 정규화](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:961>), [선택 정보 저장](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:5824>).

### F09 · P2 · 요약 창의 키보드 탐색·닫기 미흡

- **재현:** Escape로 닫히지 않는다. Tab 이동 시 숨김 처리 의도인 결과 단계로 이동한 뒤 배경 화면까지 벗어난다. 닫은 후 포커스도 숨겨진 닫기 버튼에 남는다.
- **방향:** 열린 대화상자 안에서 포커스를 순환시키고 배경을 비활성화한다. Escape 닫기와 호출 버튼으로 포커스 복귀를 연결한다. F03과 함께 처리한다.
- **근거:** [요약 창 열기·닫기·이벤트](<D:/00. Dev_Folder/Promptdeck/src/promotion.js:2415>).

### F10 · P2 · 사진+3D 추천 지침과 사진 공통 규칙 충돌

- **관찰:** ‘인물실사+3D 데이터 비주얼’ 적용 시 컨셉에는 `floating 3D charts`, `translucent dashboards`를 요구하면서 공통 사진 레이어에는 사진 공간에 뜬 반투명 3D 인터페이스를 금지한다.
- **영향:** 모델이 어느 지시를 우선할지 불명확하다. 실제 이미지가 실패했다고 판정한 것은 아니다.
- **방향:** 순수 사진+2D 편집, 사진+CGI 합성, 비사진 그래픽을 구분하고 선택한 스타일에 맞게 허용·금지 지침을 생성한다.

## 4. 기능·UI/UX 추가 개선방향

### A. 첫 화면을 ‘메시지 작성’ 중심으로 재구성

- 진입부를 ‘원문 붙여넣기 / 직접 작성 / 샘플’로 정리하고 목적·헤드라인을 바로 입력하게 한다.
- 규격은 기본값을 한 줄 요약으로 보여주고 변경할 때 펼친다. 로고·QR·고급 품질은 선택 기능으로 유지한다.
- 현재 초기 390×844 화면에서 헤드라인 시작은 문서 상단 기준 약 1,774px, 결과 영역 시작은 약 4,988px였다. 전체 문서 높이는 약 7,689px다. 빈 상태에서도 결과 확인에 여러 화면의 스크롤이 필요하다.
- 모바일에 ‘입력 / 결과’ 전환을 추가해 결과 이동을 한 번에 제공한다. 현재 하단 복사 버튼은 유지하되 복사 대상 상태를 함께 표시한다.
- 기존 다중 카드와 작은 배지의 반복을 줄이고 ‘필수 / 선택 / 고급’ 정도로 단순화한다.

### B. 프롬프트 편집 상태를 사용자 언어로 명시

- ‘자동 초안’과 ‘직접 수정본’ 중 현재 사용하는 것을 표시한다.
- ‘초안 반영’은 실제 동작이 이해되는 ‘자동 초안으로 되돌리기’로 변경한다.
- 상단 ‘레이아웃 바꾸기’와 결과 내부 ‘↻ 레이아웃’ 중 하나를 정리한다.
- ‘Edit / Save / Copy’는 ‘편집 / 저장 / 복사’로 통일한다.
- 출력 언어가 영어로 고정되어 있다는 점과 이미지 안 한글 문구는 유지한다는 점을 짧게 설명한다.
- 제작 규격 설명의 ‘대상 생성 엔진 설정’은 현재 엔진 선택이 숨겨져 있으므로 실제 화면에 맞춰 고친다.

### C. 원문 요약의 결과를 이미지용으로 조정

- 근거·신뢰도·선택 적용 구조는 유지한다. 누락·추론 구분도 보존한다.
- 테스트 원문에서 압축 후 본문에도 신청 방법과 문의처에 같은 전화번호가 반복되었다. 의미 단위 중복 제거가 필요하다.
- ‘이미지용 핵심 요약 / 상세 안내 보존’을 분리한다. 현재는 긴 구조화 본문을 적용한 직후 80자 초과 경고가 나타날 수 있다.
- 고정 80자 기준 대신 출력 비율·직접 크기·본문 항목 수·로고 및 QR 공간을 함께 고려해 정보 밀도를 안내한다.
- 분석한 새 원문에 이전 체크 상태를 계속 적용할지 정책을 정한다. 새 원문에서는 신뢰도에 따라 다시 선택하는 편이 이해하기 쉽다.

### D. 추천 정확도와 카피 사실성 강화

- 현재 수치 감지 정규식은 단위가 없는 숫자도 성과 신호로 취급한다. 연도·신청일·전화번호·모집 인원과 성과 지표를 분리한다.
- 교육 모집 원문에서 성과 리포트·3D 데이터 화풍이 우선 추천되는 사례를 확인했다. ‘목적 우선, 근거 수치 보조’로 가중치를 재설계하고 추천 이유를 구체화한다.
- 추천 카드는 이름·설명뿐 아니라 실제 스타일 썸네일을 제공해 적용 전에 비교할 수 있게 한다.
- AI 자동 오퍼·훅에는 ‘입력·원문에 없는 가격, 혜택, 인원, 날짜, 성과를 만들지 말 것’을 공통 적용한다. 관련 정보가 없으면 사실을 추가하지 않는 표현을 사용한다.
- 자동 생성 안내는 ‘이미지 생성 시 AI가 작성’으로 바꾸면 지금 이미 완성된 문구라는 오해를 줄일 수 있다.

### E. 출력 규격과 최종 제작 연결

- A4를 안내하는 빠른 규격은 현재 5:7이다. A4 210:297과 다른 비율이므로 ‘용지 근사 비율’로 명시하거나 정확한 A4 규격 프리셋을 제공한다.
- cm는 물리적 크기이며 이미지 API가 정확한 인쇄 해상도를 보장한다는 뜻은 아니다. 인쇄 모드를 추가할 때 실제 픽셀 수·해상도·최종 PDF 출력을 함께 설계한다.
- QR과 로고는 현재 합성 위치 지침이다. 다음 단계로 확장한다면 실제 QR·원본 로고를 안전하게 합성하고 최종 파일을 확인하는 흐름이 우선이다.
- 홍보 탭에 ‘이미지 생성으로 보내기’를 추가하되 F01의 공통 프롬프트 기준을 먼저 해결한다.

### F. 유지보수·테스트 정리

- 과거 기능 계획서와 현재 단일 이미지 흐름을 동기화한다. 비노출 엔진·색상·레거시 자산 유형 코드는 현행 경로와 구분한다.
- `partials/pane-promotion.html`에는 현재 index의 로고 단계·독립 결과 열 등 최신 구조가 빠져 있다. `scripts/build-html.mjs`는 이 partial로 index를 재작성하므로 재실행 시 기능이 되돌아갈 위험이 있다. 단일 원본을 결정하고 동기화 검사를 둔다. 실제로 이 빌드를 실행하지는 않았다.
- 기존 smoke의 편집 검사는 ‘편집 모드에서 복사’ 후 자동 초안으로 되돌리고 파일을 저장한다. 따라서 편집→미리보기→복사, 편집본 JSON 왕복, 섹션 Save→새로고침 결함을 놓친다.
- 모든 기능을 넓게 다시 검사하기보다 이번 재현 경로를 회귀 시나리오로 추가한다.
