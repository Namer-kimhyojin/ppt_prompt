# PromptDeck 문서 유형별 템플릿 고도화 구현계획

> 후속 개발 기준: [2026-09-08 견본 선택·실시간 조정 개발계획서](document-design-visual-workbench-development-plan-2026-09-08.md). 신규 개발 범위와 순서는 후속 문서를 따른다. 이 문서의 35개 유형 분류는 확장 자료로 보존한다.

- 문서 상태: 구현 기준안 v1.0
- 작성일: 2026-09-07
- 대상 기능: `문서 디자인`
- 목표 버전: `DocumentDesignSpec 3.0`

## 1. 결정 사항

문서 유형별 템플릿을 **내용 작성 양식**이 아닌 **시각 편집 구조**로 정의한다. 템플릿은 페이지 역할, 정보 위계, 표·차트·이미지·주석의 배치 방식과 출력 규격 기본값을 담당한다. 디자인 테마는 색상, 서체, 배경, 아이콘, 픽토그램, 이미지 분위기를 담당한다.

최종 조합은 아래 순서로 만든다.

```text
문서 유형 → 유형 템플릿 → 구성 변형 → 디자인 테마 → 느낌 조정 → 출력 형식 변환
```

예를 들어 `정책·연구보고서 + 근거 중심형 + 공공기관 보고 테마 + 차분한 색상 + A4 세로`를 선택하면, 정책보고서에 맞는 표지·장 시작·본문·근거 이미지·표/차트·요약 화면의 배치 규칙에 공공기관 테마의 색상과 서체가 적용된다. 사용자가 입력한 내용·목차·문장·사실·수치는 변경하지 않는다.

## 2. 현재 구현 진단

현재 카탈로그에는 35개 문서·출판 유형, 7개 시각 문법, 12개 디자인 테마와 6개 페이지 역할이 있다. 그러나 문서 유형 데이터는 `id`, `label`, `grammarId`, `bestFor` 네 필드만 가지며, 유형 선택 시 다음 동작만 수행한다.

1. 문서 유형에 연결된 시각 문법을 선택한다.
2. 해당 시각 문법과 호환되는 테마를 추천한다.
3. 시각 문법에 따라 특수 페이지 이름을 바꾼다.
4. 추천 목록의 첫 테마를 적용한다.

이 구조에서는 `일반 보고서`, `연차보고서`, `시장분석서`가 모두 `보고·분석형`으로 묶여 페이지 구성과 컴포넌트가 실질적으로 같아진다. `교과서`와 `자습서`, `수험서`와 `문제집`, `수필집`과 `시집`도 같은 문제가 생긴다.

## 3. 목표와 완료 기준

| 목표 | 완료 기준 |
|---|---|
| 유형별 차이를 즉시 이해 | 문서 유형을 바꾸면 템플릿 카드, 6면 미리보기, 페이지 규칙이 함께 바뀐다. |
| 템플릿과 테마의 역할 분리 | 템플릿 변경은 구조를, 테마 변경은 시각 언어를 바꾸며 서로의 선택값을 초기화하지 않는다. |
| 35개 유형 전체 지원 | 모든 유형에 독립된 `templateProfileId`, 페이지 세트, 컴포넌트 규칙, 검수 규칙이 있다. |
| 원문 보존 | 생성 결과에 내용 작성·목차 변경·요약 지시가 섞이지 않는다. |
| 모바일 완결성 | 390px 화면에서 유형 탐색, 템플릿 선택, 6면 확인, 다음 단계 이동이 가로 넘침 없이 가능하다. |
| 검증 가능성 | 템플릿 스키마, 프롬프트 계약, 이미지 자산, 브라우저 동작을 자동 검사한다. |

## 4. 제품 구조

### 4.1 문서 유형

사용자가 만들려는 결과물의 성격이다. `일반 보고서`, `교과서`, `자격증 도서`, `동화책`처럼 찾기 쉬운 이름과 용도를 제공한다.

### 4.2 유형 템플릿

문서 유형에 필요한 시각적 페이지 체계다. 다음 항목을 포함한다.

- 기본 페이지 역할과 선택 페이지 역할
- 페이지별 그리드, 여백감, 제목 위치와 정보 위계
- 표, 차트, 이미지, 캡션, 각주, 인용, 문제·해설 등 컴포넌트 사용 규칙
- 표지·장 시작·본문·이미지·데이터·특수 페이지의 구체적 화면 구성
- 권장 판형·방향·제본·맞쪽 설정
- 유형별 출력 검수 항목

### 4.3 구성 변형

같은 유형 안에서 정보 표현의 중심을 선택한다. 수치 입력 대신 의미가 분명한 2~3개 선택지만 제공한다.

- 균형형
- 데이터·근거 중심형
- 이미지·사례 중심형
- 학습·활동 중심형
- 읽기·여백 중심형

각 문서 유형에는 관련 있는 변형만 노출한다.

### 4.4 디자인 테마

현재 12개 테마를 유지하며 색상, 서체, 배경 이미지, 아이콘, 픽토그램, 다이어그램 표현과 표면 스타일을 담당한다. 템플릿의 페이지 구조를 덮어쓰지 않는다.

### 4.5 느낌 조정

현재의 정성적 조정 방식을 유지한다. 사용자는 `절제되게·균형 있게·강하게`, `촘촘하게·편안하게·여유롭게`와 같은 정도를 선택한다. 용지 크기, 방향, 도련처럼 물리적으로 정확해야 하는 항목만 명시값으로 유지한다.

## 7. 병합 규칙

각 설정의 책임을 분리해 충돌을 막는다.

| 설정 | 우선순위 |
|---|---|
| 용지·방향·제본·도련 | 사용자 명시값 → 템플릿 기본값 → 시스템 기본값 |
| 페이지 역할·그리드·컴포넌트 | 사용자 구성 변형 → 유형 템플릿 → 시각 문법 |
| 색상·서체·배경·아이콘 | 사용자 느낌 조정 → 디자인 테마 → 템플릿 권장값 |
| 표·차트·이미지 표현 | 사용자 조정 → 유형 템플릿 → 디자인 테마의 조형 규칙 |
| 검수 | 공통 필수 규칙 + 유형별 규칙 + 출력 형식별 규칙 |

테마 변경 시 `templateProfileId`와 `variantId`를 유지한다. 유형 변경 시 새 유형의 기본 템플릿을 적용하되 용지 규격과 사용자가 직접 입력한 원문은 유지한다. 호환되지 않는 세부값만 초기화하고 변경 내용을 화면에 알린다.

## 8. UI·UX 구조

### 8.1 1단계: 유형·템플릿

현재의 7개 시각 문법 칩은 사용자가 이해하기 쉬운 `업무·보고`, `전문·실무`, `교육·학습`, `수험·문제`, `문학·읽기`, `그림·서사`, `매거진·브랜드` 분류로 표시한다.

1. 상단에는 `최근 사용`, `추천`, `전체 유형`을 둔다.
2. 유형 카드는 이름, 용도, 대표 페이지 3면, 핵심 특징 2개를 표시한다.
3. 유형을 고르면 바로 아래에 해당 유형의 구성 변형 2~3개를 표시한다.
4. 변형 카드는 동일한 샘플 정보로 구조 차이를 보여준다.
5. 선택 결과를 `일반 보고서 · 결론·근거 보고 · 균형형`처럼 한 줄로 고정 표시한다.

### 8.2 2단계: 테마

현재 12개 테마 갤러리를 유지하되 상단에 다음 상태를 명확히 표시한다.

```text
적용 중인 구조: 일반 보고서 · 균형형
적용할 디자인: 공공기관 보고
```

테마 카드는 선택한 템플릿 구조에 테마를 적용한 6면 결과를 보여준다. 테마를 바꿔도 페이지 구성은 그대로 유지한다.

### 8.3 3단계: 세부 조정

공통 설정 위에 `이 템플릿의 핵심 조정` 영역을 둔다. 예를 들어 보고서는 결론 강조, 데이터 존재감, 주석 밀도를 먼저 보여주고, 동화책은 그림 존재감, 텍스트 안전 영역, 장면 변화 정도를 먼저 보여준다. 나머지 공통 조정은 `전체 설정`에서 제공한다.

### 8.4 4단계: 결과·검수

선택 요약에 다음 정보를 추가한다.

- 문서 유형
- 템플릿 이름과 버전
- 구성 변형
- 6개 페이지 역할과 적용 상태
- 디자인 테마
- 용지·방향·제본·도련
- 유형별 검수 규칙

### 8.5 모바일

- 처음에는 현재 유형에 맞는 추천 3개만 보여주고 `전체 유형 보기`를 제공한다.
- 전체 유형은 검색 가능한 전체 화면 선택 패널로 연다.
- 유형 선택 후 유형 목록을 접고 선택 요약과 구성 변형을 바로 보여준다.
- 구성 변형 카드는 한 화면 폭의 세로 카드로 표시하며 대표 3면을 함께 보여준다.
- 6면 상세 미리보기는 하단 시트에서 크게 확인하고 좌우 스와이프로 전환한다.
- 하단에는 단계 이동 버튼 하나를 유지하고, 뒤로 이동해도 유형·템플릿·테마 선택을 보존한다.
- 390×844와 375×667에서 본문 가로 스크롤, 잘린 카드, 고정 버튼 겹침이 없어야 한다.

## 9. 미리보기 자산 전략

### 9.1 1차 구현

- 35개 문서 유형마다 기본 템플릿 1개를 만든다.
- 템플릿마다 표지·장 시작·본문·이미지·표/차트·특수 페이지 6면을 만든다.
- 총 210개의 실제 미리보기 이미지를 생성한다.
- 이미지 역할에는 저장소의 실제 스타일 자산이나 권리가 확인된 이미지를 사용한다.
- 카드용 썸네일은 3면 합성 WebP, 상세 화면은 6면 WebP를 지연 로딩한다.

### 9.2 2차 구현

사용 빈도가 높은 12개 유형에 구성 변형 2개씩을 추가한다.

- 일반 보고서
- 기획서·사업계획서
- 제안서
- 정책·연구보고서
- 연차·성과보고서
- 매뉴얼·가이드
- 교과서
- 자습서
- 자격증 도서
- 수필집
- 동화책
- 매거진

추가 변형은 12개 유형 × 2개 × 6면으로 144개다. 초기 화면에서는 카드용 썸네일만 불러오고 상세 6면은 사용자가 선택했을 때 로딩한다.

### 9.3 생성기

기존 `scripts/generate-document-design-previews.mjs`의 렌더링 코드를 공통 모듈로 분리하고 `scripts/generate-document-template-previews.mjs`를 추가한다. 모든 이미지는 같은 샘플 데이터, 크기, 렌더링 환경으로 생성해 구조 차이를 비교할 수 있게 한다.

## 10. 프롬프트 계약 3.0

`DocumentDesignSpec 3.0`에는 다음 필드를 추가한다.

```json
{
  "template": {
    "profileId": "business-report.standard",
    "catalogVersion": 1,
    "variantId": "balanced",
    "publicationTypeId": "business-report",
    "pageSet": [],
    "componentProfile": {},
    "requiredRules": [],
    "avoidRules": []
  }
}
```

사람이 읽는 프롬프트에는 아래 순서로 출력한다.

1. 원문 불변 원칙
2. 물리 규격
3. 문서 유형과 유형 템플릿
4. 페이지 역할별 시각 구조
5. 디자인 테마와 색상·서체 규칙
6. 정성적 느낌 조정
7. 표·차트·이미지·다이어그램 규칙
8. 장문 일관성
9. 유형별·출력 형식별 검수

페이지 역할 설명에는 `이 페이지에 어떤 내용을 새로 써라`는 지시를 넣지 않는다. `입력된 내용 중 해당 역할의 정보를 이 시각 구조로 배치한다`는 편집 지시만 출력한다.

## 12. 구현 단계

### 단계 1. 스키마와 카탈로그

- 35개 유형의 기본 템플릿 프로필 작성
- 유형별 페이지 세트와 컴포넌트 규칙 정의
- 기존 저장 상태를 3.0으로 올리는 마이그레이션 추가
- 중복 ID, 누락 역할, 존재하지 않는 레시피를 검사하는 단위 테스트 추가

완료 기준: 모든 유형이 독립된 템플릿 서명을 가지며 동일한 프로필을 그대로 공유하지 않는다.

### 단계 2. 미리보기 생성 체계

- 페이지 레시피 렌더러와 이미지 생성기 분리
- 35개 기본 템플릿의 210개 상세 이미지 생성
- 카드용 3면 합성 썸네일 생성
- 이미지 크기·포맷·경로·중복 해시 검사 추가

완료 기준: 유형을 바꾸면 대표 3면과 상세 6면의 구조 차이가 눈에 보인다.

### 단계 3. 유형·변형 선택 UX

- 7개 분류, 추천 3개, 전체 검색 구현
- 유형 카드와 구성 변형 카드 구현
- 선택 요약, 변경 알림, 상태 보존 구현
- 모바일 전체 화면 선택기와 상세 미리보기 하단 시트 구현

완료 기준: 처음 방문한 사용자가 3번 이내의 선택으로 유형과 템플릿을 확정할 수 있다.

### 단계 4. 테마 결합과 세부 조정

- 템플릿 구조와 테마 토큰의 병합 엔진 구현
- 유형별 핵심 조정 우선 노출
- 테마 변경 시 템플릿 유지, 유형 변경 시 명시 규격 유지
- 호환되지 않는 설정의 선택적 초기화와 안내 구현

완료 기준: 같은 템플릿에서 테마만 바뀌고, 같은 테마에서 템플릿만 바뀌는 차이가 각각 명확하다.

### 단계 5. 프롬프트·검수·배포

- `DocumentDesignSpec 3.0`과 텍스트 프롬프트 출력
- 원문 불변, 시각 편집 전용, 페이지 역할별 규칙 검사
- 35개 유형 × 주요 출력 형식 계약 테스트
- 데스크톱·모바일·정적 빌드·운영 자산 검사

완료 기준: 전체 회귀 검사와 고정 배포 URL 검증을 통과한다.

### 단계 6. 확장 변형

- 우선 12개 유형에 2개 추가 변형 구현
- 최근 사용, 즐겨찾기, 두 템플릿 비교 기능 추가
- 사용 빈도와 이탈 지점을 바탕으로 나머지 유형의 변형 우선순위 결정

## 13. 자동 검수 기준

- 35개 유형 모두 고유 `templateProfileId`와 기본 변형이 있다.
- 각 기본 템플릿에 6개 페이지 역할과 6개 고유 미리보기 경로가 있다.
- 유형 변경 전후 최소 3개 페이지의 `recipeId`가 달라진다.
- 테마 변경 후에도 유형·템플릿·변형·용지 규격이 유지된다.
- 유형 변경 후에도 원문과 사용자가 명시한 물리 규격이 유지된다.
- 생성 프롬프트에 템플릿 ID·버전·페이지 세트·컴포넌트·검수 규칙이 포함된다.
- 생성 프롬프트에 내용 생성, 목차 재작성, 사실 보완 지시가 포함되지 않는다.
- 모든 미리보기 파일이 실제 이미지이며 확장자와 파일 시그니처가 일치한다.
- 한 템플릿 안의 6면 이미지 해시가 서로 다르다.
- 390×844와 375×667에서 본문 가로 넘침이 없고 하단 버튼이 콘텐츠를 가리지 않는다.
- 키보드만으로 유형·변형·테마·미리보기 탭을 선택할 수 있다.
- 선택 상태가 새로고침 후 복원되고 2.0 저장 데이터가 3.0으로 정상 이전된다.

## 14. 성능 기준

- 첫 화면에는 추천 유형 3개의 카드용 썸네일만 우선 로딩한다.
- 전체 유형 이미지는 지연 로딩한다.
- 카드용 WebP는 파일당 80KB 이하, 상세 WebP는 파일당 180KB 이하를 목표로 한다.
- 선택 반응과 미리보기 교체는 캐시 상태에서 300ms 이내를 목표로 한다.
- 자산 로딩 실패 시 이미지 없는 빈 상자 대신 유형 이름, 페이지 역할, 재시도 버튼을 표시한다.

|---|---|

| 템플릿과 테마의 차이가 다시 모호해짐 | UI와 데이터 책임을 분리하고 `구조`와 `디자인` 상태를 항상 함께 표시한다. |
| 유형×변형×테마 조합으로 자산이 급증 | 템플릿 구조 미리보기와 테마 토큰을 분리하고 카드·상세 이미지를 지연 로딩한다. |

## 16. 우선 구현 범위

첫 구현은 35개 유형의 기본 템플릿과 210개 미리보기, 유형·템플릿·테마 분리, 스키마 3.0, 모바일 선택 흐름까지를 P0로 한다. 추가 구성 변형 144개, 즐겨찾기, 비교 보기는 P1로 분리한다.

이 범위가 완료되면 문서 유형 선택은 단순 추천 필터가 아니라 실제 페이지 구조와 편집 규칙을 결정하는 기능이 된다. 이후 사용 빈도가 높은 유형부터 구성 변형을 늘려도 데이터 구조와 화면 흐름을 다시 바꿀 필요가 없다.
