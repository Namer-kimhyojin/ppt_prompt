# PromptDeck UI/UX 통합 규칙

## 적용 목표

모든 탭을 같은 작업 흐름으로 보이게 한다. 사용자는 어느 탭에서든 **왼쪽에서 입력·설정하고, 오른쪽에서 결과·미리보기를 확인하며, 같은 위치에서 핵심 작업을 실행**할 수 있어야 한다.

## 공통 작업 공간

- 데스크톱(961px 이상): 입력/설정 패널과 결과/미리보기 패널을 나란히 배치한다. 각 탭의 콘텐츠 폭 비율은 달라도 두 패널의 시작선, 바깥 여백, 카드 간격은 맞춘다.
- 시각 검토가 핵심인 `슬라이드 프롬프트`의 미리보기 열은 큰 화면에서 500px을 사용한다. 1280px 미만에서는 설정 영역을 보호하기 위해 410px부터 화면 폭에 맞춰 유동적으로 확장한다.
- 태블릿(721–960px): 한 열로 전환하거나 결과 패널을 다음 행으로 보낸다. 데스크톱용 고정 패널은 해제한다.
- 모바일(720px 이하): 단일 열과 14px의 좌우 여백을 사용한다. 상단 우측 액션 도크는 숨기고, 각 탭의 본문 또는 하단 액션을 사용한다.
- 기본 외부 여백은 `--workspace-gutter`, 탭 내 주요 영역 간격은 `--workspace-gap`, 카드 내부 여백은 `--panel-padding` 토큰을 사용한다.

## 패널과 정보 위계

- 상위 패널은 `surface + 1px line + radius-lg + shadow-soft` 조합을 사용한다.
- 화면 UI의 글자는 12px보다 작게 사용하지 않는다. `12px 보조 정보 → 13px 레이블 → 14px 본문·제어 → 16px 부제 → 19px 패널 제목 → 23px 페이지 제목`의 공통 스케일을 사용한다. 단, 실제 출력 비율을 재현하는 슬라이드·인쇄 축소 미리보기 내부 문자는 예외로 둔다.
- 패널 머리글은 제목, 짧은 설명, 상태 배지를 한 줄의 공통 위계로 둔다. 제목은 19px, 설명은 14px을 기본으로 한다.
- 보조 설정과 안내는 중첩 카드를 남발하지 않고 `surface-alt` 배경의 얕은 블록 또는 접기 영역으로 처리한다.
- 기능 수가 적은 유틸리티 탭은 큰 카드를 반복해 공간을 채우지 않는다. `입력 → 조정 → 결과 활용`의 3단계 위계를 유지하되, 반복 선택지는 낮은 세그먼트형 제어로 묶고 고급 설정·긴 안내는 기본 접기 영역으로 제공한다.
- 자주 쓰는 조합은 빠른 프리셋으로 제공하고, 프리셋 적용 후에도 세부 설정에서 값을 직접 조정할 수 있어야 한다.
- 입력 필드 묶음 간 간격은 16px, 관련 제어 요소 간 간격은 8px, 섹션 간 간격은 20px을 기본으로 한다.
- 같은 단계 안에서 반복되는 설정 카드는 가로·세로 모두 16px의 동일한 간격을 사용하며, 카드별 임의 여백을 섞지 않는다.
- 비주얼 믹서의 5색 팔레트는 슬라이드 프롬프트에서 `Primary·Secondary·Accent·Background·Text Primary` 다섯 역할로 모두 보존한다. 카드 표면·보조 텍스트·구분선만 역할 색상에서 파생한다.

## 빠른 작업 규칙

- 데스크톱: 활성 탭의 우측 결과 열에 `#tabActions`를 **일반 흐름을 차지하는 독립 작업 패널**로 둔다. 퀵버튼 도크와 결과 패널은 같은 카드의 부모·자식이 아니라 전용 `tab-action-column` 안의 형제 카드여야 한다. 두 카드 사이에는 `--workspace-gap`(20px)을 한 번만 적용하고, 콘텐츠 위에 뜨거나 sticky 레이어로 겹치지 않게 한다. 핵심 작업은 최대 3개까지만 직접 표시한다.
- 우선순위: 결과 생성/실행은 `primary`, 복사·가져오기·적용은 `secondary`, 샘플·초기화·다운로드·상태 확인은 `더보기` 또는 `ghost`로 둔다.
- 버튼은 동사 중심의 짧은 이름으로 쓴다. 한 탭 안에서 같은 기능은 같은 표현을 사용한다. 예: `프롬프트 생성`, `프롬프트 복사`, `샘플 채우기`, `초기화`.
- 모바일에서는 액션 도크를 노출하지 않는다. 해당 작업을 본문 또는 기존 하단 액션에서 같은 우선순위로 제공한다.
- 결과 패널과 액션 도크 때문에 별도 스크롤 영역을 만들지 않는다. 긴 결과는 페이지 자체를 스크롤하고, 내부 스크롤은 편집기·코드 출력처럼 독립적인 조작이 필요한 경우에만 허용한다.

## 상태와 접근성

- 선택 상태는 색상만으로 구분하지 않고 테두리·배경·아이콘/텍스트를 함께 바꾼다.
- 단계 완료 상태는 카드 전체를 성공색으로 물들이지 않고 중성 패널색을 유지한다. 현재 활성 단계만 공통 강조색 테두리로 구분한다.
- 모든 포커스 가능한 제어 요소는 공통 `focus-visible` 윤곽선을 유지한다.
- 오류, 완료, 진행 상태는 의미 색상을 사용하되 일반적인 선택·강조색으로 사용하지 않는다.
- 다크모드에서는 탭별 고유 배경색을 만들지 않고 공통 중성 팔레트 토큰을 우선 사용한다.

## 구현 원칙

- 기능별 클래스와 탭 ID는 유지한다. 공통 스타일은 토큰과 얕은 보정 선택자로 해결하고, 기존 기능 로직을 변경하지 않는다.
- 새 화면 요소는 기존 `btn`/`gen-btn`, `tab-action-dock`, 공통 테마 토큰을 우선 재사용한다.
- 새 탭 또는 대규모 탭 수정 시에는 이 문서의 데스크톱·태블릿·모바일 규칙과 액션 우선순위를 함께 적용한다.
