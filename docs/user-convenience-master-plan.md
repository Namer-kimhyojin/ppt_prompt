# PromptDeck 사용자 편의성 강화 종합계획

## 1. 계획 목적

PromptDeck의 많은 기능을 줄이는 것이 아니라, 사용자가 다음 세 가지 질문에 즉시 답할 수 있도록 제품 경험을 재구성한다.

1. **어디서 시작해야 하는가?**
2. **지금 무엇을 입력하고 있으며 다음에는 무엇을 해야 하는가?**
3. **만든 결과를 어디에서 확인하고 다음 작업으로 어떻게 넘기는가?**

최종 목표는 처음 쓰는 사용자도 설명서 없이 핵심 결과를 만들고, 반복 사용자는 적은 클릭으로 이전 설정을 재사용하며, 오류가 발생해도 입력 내용을 잃지 않고 작업을 이어가는 것이다.

---

## 2. 검토 범위와 근거

### 검토 범위

- 상단 11개 기능 탭과 탭 간 이동
- 입력·설정·미리보기·결과 복사/다운로드 흐름
- 덱 제작 핵심 흐름: `덱 디자인 가이드 → 슬라이드 분리기 → 슬라이드 이미지 생성`
- 비주얼 기획 흐름: `컨셉 제안 → 비주얼 믹서 → 홍보/양식 이미지 적용`
- 특수 결과물 흐름: 지도, 부속 양식, 양식 이미지, 홍보용 이미지, QR코드
- 데스크톱·태블릿·모바일 반응형
- 저장·복구·초기화·오류 안내·접근성

### 검토 근거

- `index.html`의 현재 11개 탭 구조
- `src/tabs.js`의 탭별 액션 도크와 탭 간 프록시 액션
- `docs/ui-ux-system.md`의 공통 작업 공간·타이포그래피·액션 원칙
- 지도 이미지 UX 계획, 기존 Design QA 기록, 자동 스모크 테스트 항목
- 각 탭의 상태 저장, 초기화, 복사, 전송, 다운로드 구현

### 증거 한계

현재 작업 환경에서는 인앱 브라우저를 통한 신규 화면 캡처가 불가능했다. 따라서 이 문서는 정식 화면 감사 보고서가 아니라 **현재 구현과 검증 규칙을 기반으로 한 실행 계획**이다. 1단계 착수 시 실제 사용자 과업 관찰과 화면 캡처로 우선순위를 보정한다.

## 3. 현재 기반과 주요 편의성 위험

### 유지·확대할 강점

1. 대부분의 탭이 `왼쪽 입력 → 오른쪽 결과`라는 공통 구조를 갖고 있다.
2. 데스크톱 핵심 액션을 우측 결과 열 상단에 모으는 액션 도크가 구현되어 있다.
3. 모바일에서는 데스크톱 액션 도크를 숨기고 본문 또는 하단 액션을 사용하는 원칙이 있다.
4. 덱 디자인 가이드와 지도 탭은 핵심 선택을 먼저 보여주고 고급 설정을 접는 방식으로 개선되어 있다.
5. 자동 저장, 상태 복원, 탭 간 값 전달, 스모크 테스트 등 편의성 향상을 지탱할 기술 기반이 이미 존재한다.

### 핵심 위험

| 구분 | 현재 위험 | 사용자 영향 | 우선순위 |
|---|---|---|---|
| 탐색 | 11개 기능이 동일한 위계의 탭으로 나열됨 | 시작 위치와 기능 관계를 이해하기 어려움 | P0 |
| 시작점 | 첫 탭이 `슬라이드 프롬프트(구)` | 신규 사용자가 이전 도구부터 시작할 가능성 | P0 |
| 작업 연속성 | 탭별 상태 저장 방식과 저장 범위가 서로 다름 | 어느 값이 보존되는지 예측하기 어려움 | P0 |
| 탭 간 전달 | 보내기·가져오기·적용 기능은 있으나 전체 경로가 보이지 않음 | 작업이 다음 단계로 넘어갔는지 확신하기 어려움 | P0 |
| 결과 행동 | `복사`, `현재 복사`, `전체 복사`, `프롬프트 복사` 등 표현이 혼재 | 비슷한 버튼의 차이를 다시 읽어야 함 | P1 |
| 오류 회복 | 일부 기능은 기본 확인창, 일부는 상세 상태 안내 사용 | 오류·초기화·덮어쓰기 경험이 탭마다 다름 | P1 |
| 정보 밀도 | 기능이 많은 탭에서 설정과 설명이 동시에 노출됨 | 첫 결과까지 시간이 길어짐 | P1 |
| 모바일 | 긴 탭 목록과 복잡한 설정의 탐색 비용이 큼 | 핵심 작업보다 스크롤·탭 탐색에 시간 소요 | P1 |
| 접근성 | 탭별 구현 시기와 컴포넌트가 달라 상호작용 규칙이 다를 수 있음 | 키보드·보조기기 사용의 예측 가능성 저하 | P1 |
| 용어 | 내부 기술 용어와 사용자 과업 용어가 일부 혼재 | 기능을 실행하기 전 효과를 이해하기 어려움 | P2 |

## 4. 목표 사용자 경험

### 4.1 제품 구조

11개 평면 탭을 다음 네 개 작업군으로 이해할 수 있게 한다. 기능 자체와 기존 탭 ID는 유지하되 탐색 UI만 목적 중심으로 정리한다.

| 작업군 | 포함 기능 | 대표 사용자 목표 |
|---|---|---|
| 덱 제작 | 덱 디자인 가이드, 슬라이드 분리기, 슬라이드 이미지 생성 | 발표자료 전체를 일관된 이미지로 제작 |
| 비주얼 기획 | 컨셉 제안, 비주얼 믹서 | 주제·화풍·팔레트 방향 결정 |
| 특수 이미지 | 지도 이미지, 부속 양식, 양식 이미지, 홍보용 이미지, QR코드 | 특정 결과물 빠르게 제작 |
| 이전 도구 | 슬라이드 프롬프트(구) | 기존 작업 방식 유지·이관 |

데스크톱에서는 작업군과 하위 기능을 분리해 표시하고, 모바일에서는 현재 작업군을 한 번에 바꿀 수 있는 간결한 메뉴를 제공한다. 별도의 장식성 홈 화면을 추가하지 않고 마지막 작업 또는 권장 시작 탭을 즉시 연다.

### 4.2 핵심 덱 제작 흐름

```text
덱 디자인 가이드
  → 슬라이드 분리기
    → 슬라이드 이미지 생성
      → 결과 확인·재시도·내보내기
```

각 단계는 다음 항목을 공통으로 보여준다.

- 현재 단계와 다음 단계
- 이전 단계에서 가져온 값
- 아직 필요한 입력
- 자동 저장 상태
- 현재 단계의 대표 행동 한 개
- 다음 단계로 이동했을 때 유지되는 항목

### 4.3 단일 탭의 공통 흐름

모든 탭은 다음 네 단계 중 필요한 것만 사용한다.

1. **시작**: 목적 또는 빠른 예시 선택
2. **입력·조정**: 핵심값 우선, 세부값은 필요할 때만
3. **확인**: 미리보기·준비 상태·오류 확인
4. **활용**: 생성·복사·다운로드·다음 탭 적용

## 5. 개선 전략

### 전략 A. 탐색과 시작점 단순화

1. 첫 기본 탭을 `덱 디자인 가이드`로 변경한다.
2. `슬라이드 프롬프트(구)`는 `이전 도구` 작업군으로 이동하고 새 흐름으로 옮기는 안내를 제공한다.
3. 최근 사용 탭과 진행 중 작업이 있으면 마지막 위치에서 재개한다.
4. 탭 이름은 결과물 또는 과업 중심으로 통일한다.
5. 모바일에서는 11개 탭을 한 줄로 계속 넘기지 않고 작업군 단위로 찾게 한다.

**완료 기준**

- 처음 방문한 사용자가 10초 안에 덱 제작 시작 위치를 찾는다.
- 모든 기능이 두 번 이하의 탐색 행동으로 열릴 수 있다.
- 현재 작업군과 선택한 기능이 색상 외의 방법으로도 구분된다.

### 전략 B. 입력 부담과 판단 피로 축소

1. 각 탭의 첫 화면에는 결과에 영향이 큰 핵심 선택만 노출한다.
2. 서술형 입력은 선택지로 대체 가능한지 먼저 검토한다.
3. 자유 입력이 필요한 경우 예시 한 개, 글자 수, 결과 반영 위치만 안내한다.
4. 고급 설정은 단순히 숨기지 않고 `언제 필요한지`를 summary에 표시한다.
5. 프리셋을 적용한 뒤 세부값을 수정할 수 있게 하고, 수정된 프리셋임을 표시한다.
6. 빈 상태에서도 최소 기본값으로 결과를 만들 수 있게 한다.

**완료 기준**

- 핵심 결과 생성 전에 필수 서술형 입력은 탭별 최대 3개를 넘지 않는다.
- 주요 탭은 예시 또는 프리셋을 선택한 뒤 3분 안에 첫 결과를 만든다.
- 고급 설정을 열지 않아도 유효한 결과가 생성된다.

### 전략 C. 탭 간 작업 연속성 강화

1. `PromptDeck 작업`이라는 공통 프로젝트 상태를 도입한다.
2. 프로젝트에는 덱 디자인 가이드, 원문 MD, 분리된 슬라이드, 비주얼 조합, 생성 설정을 선택적으로 묶는다.
3. `보내기`, `가져오기`, `적용`을 누르면 전달 항목을 짧게 미리 보여준다.
4. 다음 탭으로 이동한 뒤 `이전 단계에서 가져옴` 상태와 되돌리기 기능을 제공한다.
5. 상단 또는 결과 열에 `다음 작업`을 한 개만 추천한다.

**완료 기준**

- 덱 디자인 가이드에서 이미지 생성까지 복사·붙여넣기 없이 이동한다.
- 탭 간 전달 후 값 누락과 중복이 자동 검사된다.
- 사용자가 전달 전후 상태를 한 단계 되돌릴 수 있다.

### 전략 D. 저장·복구·초기화 신뢰 강화

1. 탭마다 다른 저장 방식을 공통 저장 상태 컴포넌트로 통합한다.
2. `저장 중`, `저장됨`, `저장 실패`, `복구됨`을 같은 위치와 문구로 표시한다.
3. 초기화 범위를 `현재 항목`, `현재 탭`, `전체 작업`으로 명확히 구분한다.
4. 초기화·프리셋 덮어쓰기·수동 편집 덮어쓰기에는 영향 범위를 표시한다.
5. 중요한 변경은 짧은 undo 이력으로 복원한다.
6. 프로젝트 JSON 내보내기·가져오기에 스키마 버전과 마이그레이션 규칙을 둔다.

**완료 기준**

- 새로고침 후 진행 중이던 핵심 입력과 활성 단계가 복원된다.
- 사용자가 의도하지 않은 초기화로 작업을 잃는 경로가 없다.
- 저장 실패 시 입력은 화면에 남고 재시도 방법이 제공된다.

### 전략 E. 결과·액션·상태 피드백 통일

1. 액션 우선순위를 `만들기 → 확인/복사 → 다음 단계 → 기타`로 통일한다.
2. 직접 노출하는 버튼은 세 개 이하로 유지한다.
3. 버튼명은 대상이 필요한 경우 대상을 함께 쓴다.
   - `복사` → `현재 프롬프트 복사`
   - `전체 복사` → `전체 슬라이드 복사`
   - `outputs 열기` → `결과 폴더 열기`
4. 비활성 버튼에는 비활성 이유를 인접 안내 또는 접근성 설명으로 제공한다.
5. 성공 토스트만으로 중요한 상태를 전달하지 않고 결과 패널에도 지속 상태를 남긴다.
6. 생성·대기·실패·재시도·취소 상태를 모든 API 작업에서 같은 패턴으로 표시한다.

**완료 기준**

- 같은 행동은 모든 탭에서 같은 용어와 시각 우선순위를 사용한다.
- 실패한 생성 작업은 입력을 유지한 채 한 번의 행동으로 재시도할 수 있다.
- 비활성 핵심 버튼의 이유를 화면 또는 보조기기에서 확인할 수 있다.

### 전략 F. 모바일·접근성·가독성 강화

1. WCAG 2.2 AA를 접근성 목표로 둔다.
2. 작업 UI 텍스트는 12px 이상, 본문·제어는 14px을 기본으로 한다.
3. 모바일 주요 터치 영역은 44×44px 이상을 목표로 한다.
4. 모든 선택 상태는 색상과 함께 테두리·배경·텍스트/아이콘 변화로 표현한다.
5. 탭·아코디언·대화상자·메뉴·슬라이더를 키보드만으로 조작할 수 있게 한다.
6. 동적 상태는 필요한 경우 `aria-live`로 알리고 포커스를 임의로 빼앗지 않는다.
7. 320px 폭, 200% 확대, 다크모드, reduced motion을 공통 검증 항목에 포함한다.

**완료 기준**

- 핵심 흐름에서 키보드 트랩이 없다.
- 320px 이상에서 가로 스크롤 없이 핵심 작업을 완료한다.
- 모든 폼 제어에 프로그램적으로 연결된 이름과 오류 설명이 있다.

### 전략 G. 도움말과 학습 비용 축소

1. 장문의 상단 안내 대신 현재 행동에 필요한 짧은 설명을 가까이 둔다.
2. `샘플 채우기`는 단순 데모가 아니라 사용자가 수정 가능한 좋은 시작점으로 제공한다.
3. 첫 사용 시 전체 투어 대신 세 가지 핵심 과업만 안내한다.
   - 덱 전체 만들기
   - 특수 이미지 하나 만들기
   - 비주얼 조합을 다른 탭에 적용하기
4. 결과 패널에는 `이 결과가 어디에 쓰이는지`와 다음 행동을 한 줄로 설명한다.
5. 오류 메시지는 원인, 영향, 해결 행동 순서로 작성한다.

## 6. 탭별 개선 계획

| 탭 | 단기 개선 | 중기 개선 | 완료 기준 |
|---|---|---|---|
| 슬라이드 프롬프트(구) | 첫 탭에서 제외, 이전 도구 배지 | 새 덱 디자인 가이드로 설정 이전 | 신규 사용자의 기본 진입 경로에서 제외 |

## 7. 실행 로드맵

### 0단계. 기준선 확정 — 3~5일

**목표:** 추정이 아니라 실제 과업을 기준으로 개선 순서를 고정한다.

- 핵심 사용자 3유형 정의: 첫 사용자, 반복 제작자, 관리자/운영자
- 대표 과업 8개와 성공 조건 정의
- 현재 소요시간, 오류, 되돌아가기, 포기 지점 측정
- 1440px·960px·720px·390px 화면 캡처 및 접근성 기본 점검
- 탭별 필수 입력·출력·저장 키·전달 계약 목록화

**산출물:** 기준선 보고서, 사용자 과업 지도, P0 백로그 확정본

### 1단계. 빠른 편의성 개선 — 1~2주

**목표:** 기능 구조를 크게 바꾸지 않고 탐색과 행동 혼란을 먼저 줄인다.

- 기본 진입 탭을 덱 디자인 가이드로 변경
- 탭 작업군과 이전 도구 구분
- 액션 이름·우선순위·더보기 규칙 통일
- 비활성 이유, 빈 상태, 성공·오류 상태 문구 통일
- 초기화 영향 범위와 되돌리기 안내 보완
- 마지막 탭·펼친 단계·스크롤 복원
- 모바일 탭 탐색과 하단 핵심 액션 정리

**출시 조건:** 주요 탭 데스크톱·모바일 스모크 테스트, 용어 사전, 파괴적 동작 테스트 통과

### 2단계. 핵심 흐름 연결 — 2~4주

**목표:** 덱 제작 과정에서 복사·붙여넣기와 상태 불확실성을 제거한다.

- 공통 프로젝트 상태와 버전 스키마 도입
- 덱 디자인 가이드 → 분리기 → 이미지 생성 전달 미리보기
- 전달 후 출처·적용 시각·되돌리기 표시
- 공통 저장 상태 컴포넌트와 복구 흐름
- 분리기 준비 상태에서 오류 위치로 직접 이동
- 이미지 생성 큐 재시도·중단 후 재개

**출시 조건:** 새로고침·탭 이동·전달·스키마 마이그레이션 회귀 테스트 통과

### 3단계. 탭별 생산성 개선 — 3~6주

**목표:** 반복 사용자의 클릭 수와 재입력을 줄인다.

- 최근 작업·즐겨찾기·프리셋 관리
- 기관정보·색상·비주얼 조합의 선택적 재사용
- 지도·양식·홍보·QR의 목적별 빠른 시작
- 결과 이름, 다운로드 형식, 결과 폴더 안내 통일
- 샘플을 실제 수정 가능한 작업 시작점으로 재정비

**출시 조건:** 탭별 대표 과업 1개 이상 자동화 검증, 5명 이상 사용성 점검

### 4단계. 접근성·성능·품질 고도화 — 지속

**목표:** 기능 추가와 관계없이 편의성 품질이 유지되는 체계를 만든다.

- WCAG 2.2 AA 점검표와 키보드 시나리오 자동화
- 320px·200% 확대·다크모드·reduced motion 검증
- 큰 프리셋 목록의 검색·지연 렌더링·가상화 검토
- 공통 컴포넌트와 탭별 예외 스타일 축소
- 성능 예산과 콘솔 오류 0 기준 운영

## 10. 검증 계획

### 자동 검증

- 11개 탭 표시·전환·액션 도크 위치
- 작업군별 탐색과 활성 상태

- 저장·새로고침·복구·초기화·undo

- 생성 큐 성공·부분 실패·재시도·취소
- 1440px·960px·720px·390px·320px 가로 넘침
- 키보드 포커스 순서, Escape 닫기, 포커스 복귀
- 다크모드·200% 확대·reduced motion
- UTF-8, JavaScript 문법, diff 검사, 콘솔 오류

### 사용성 검증

각 사용자에게 다음 대표 과업을 수행하게 한다.

1. 공공기관 발표자료용 덱 디자인 가이드 만들기
2. MD를 슬라이드별로 분리하고 누락 수정하기
3. 분리 결과를 이미지 생성 탭으로 보내 첫 장 생성하기
4. 지도 강조 프롬프트 만들기
5. 비주얼 조합을 홍보용 이미지에 적용하기
6. 부속 양식 표지와 간지 만들기
7. QR코드를 만들고 PNG로 저장하기
8. 브라우저를 새로고침한 뒤 이전 작업 이어가기

과업별로 성공 여부, 시간, 잘못 누른 행동, 질문, 되돌아가기, 입력 손실을 기록한다.

## 11. 구현 원칙

1. 기존 탭 ID와 핵심 기능 로직은 가능한 한 유지한다.
2. 새 공통 UI는 `styles/ui-system.css`, 공통 토큰, 기존 버튼·패널 구조를 우선 재사용한다.
3. 큰 파일을 전체 재작성하지 않고 작은 단위로 패치한다.
4. 한 번에 전 탭을 재설계하지 않고 공통 패턴 하나를 완성한 뒤 순차 적용한다.
5. 고급 기능을 삭제하지 않고 기본 흐름에서만 뒤로 배치한다.
6. 로컬 저장 스키마 변경 시 이전 상태 마이그레이션과 롤백 경로를 함께 제공한다.
7. 사용자 편의성 개선은 스모크 테스트와 접근성 완료 기준을 충족해야 완료로 본다.

## 13. 최종 완료 기준

다음 조건을 모두 만족하면 사용자 편의성 강화 1차 계획을 완료한 것으로 본다.

- 사용자가 제품의 기능을 작업 목적별로 이해할 수 있다.
- 신규 사용자의 기본 시작점이 이전 도구가 아니다.
- 덱 디자인 가이드에서 이미지 생성까지 복사·붙여넣기 없이 이어진다.
- 각 탭의 핵심 입력, 결과, 대표 행동이 첫 화면에서 구분된다.
- 저장·복구·초기화·오류·성공 상태가 모든 탭에서 같은 방식으로 표현된다.
- 주요 파괴적 행동은 영향 범위가 명확하고 되돌릴 수 있다.
- 대표 과업을 키보드만으로 수행할 수 있다.
- 320px 이상 화면과 200% 확대에서 핵심 작업이 가로로 잘리지 않는다.
- 전체 스모크 테스트와 탭별 대표 과업 테스트가 통과한다.
- 기준선 대비 첫 결과 시간, 완료율, 오류 회복률이 목표 수준으로 개선된다.

## 14. 권장 착수 순서

첫 구현 묶음은 아래 다섯 항목으로 제한한다.

3. `슬라이드 프롬프트(구)`를 이전 도구로 이동
