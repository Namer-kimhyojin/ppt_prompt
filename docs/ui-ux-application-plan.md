# PromptDeck 데스크톱·모바일 앱형 UI/UX 개선 계획

## 목표

PromptDeck를 여러 웹 도구가 이어 붙은 화면이 아니라, 하나의 작업용 애플리케이션처럼 인식되도록 정리한다. 사용자는 현재 위치, 다음 행동, 저장 상태를 별도로 해석하지 않고도 바로 작업을 이어갈 수 있어야 한다.

## 공통 원칙

- 한 시점에는 하나의 탐색 계층만 강조한다.
- 데스크톱은 작업 공간을 넓게 유지하고, 모바일은 현재 작업과 다음 행동만 노출한다.
- 자주 쓰는 동작은 직접 노출하고 나머지는 메뉴·서랍·상세 패널로 단계적으로 연다.
- 선택 상태, 저장 상태, 오류와 완료 피드백은 위치와 표현을 일관되게 유지한다.
- 모든 모바일 조작 대상은 최소 44px, 키보드 포커스와 닫기 동작은 예측 가능하게 유지한다.

## 화면 구조 기준

### 데스크톱

1. 64px 앱 바: 브랜드, 계정, 테마 같은 전역 기능만 배치한다.
2. 44px 도구 탐색: 작업군과 도구 전환만 담당한다.
3. 작업별 명령 바: 현재 프로젝트와 핵심 명령을 배치한다.
4. 작업 면: 입력·캔버스·결과 또는 캔버스·속성 구조를 탭 특성에 맞게 사용한다.
5. 상태 영역: 저장, 검증, 현재 선택, 단축키를 작업 흐름과 분리한다.

### 모바일

1. 56px 앱 바: 브랜드, 현재 도구, 도구 전환, 테마만 표시한다.
2. 도구 서랍: 작업군과 전체 도구를 2열 목록으로 제공한다.
3. 현재 작업: 한 번에 하나의 핵심 패널을 보여준다.
4. 하단 영역: 단계 탐색 또는 핵심 실행 버튼 중 해당 작업에 필요한 한 종류만 고정한다.
5. 상세 편집: 전체 화면 서랍으로 열고 Escape·닫기 후 원래 위치로 포커스를 돌린다.

## 단계별 적용

### 1단계 — 앱 셸과 탐색 통합

- 데스크톱 헤더와 도구 탭의 높이·간격·활성 상태를 통일한다.
- 모바일의 2단 탭 바를 숨기고 앱 바에서 여는 전체 도구 서랍으로 대체한다.
- 현재 활성 도구명을 모바일 앱 바에 표시한다.

### 2단계 — 탭별 작업 레이아웃 수렴

- 생성형 탭은 `입력 → 결과`, 편집형 탭은 `캔버스 → 속성`, 단계형 탭은 `단계 → 현재 작업` 구조로 분류한다.
- 우측 액션 도크의 직접 노출 동작은 최대 3개로 제한한다.
- 카드 중첩, 반복 제목, 중복 버튼을 제거한다.

### 3단계 — 상태와 피드백 통합

- 저장·검증·오류·완료 메시지의 위치와 색상을 공통 규칙으로 통합한다.
- 파괴적 동작은 복구 또는 명확한 확인 흐름을 제공한다.
- 빈 상태와 로딩 상태에서 다음 행동을 한 문장으로 안내한다.

### 4단계 — 접근성·품질 기준 고정

- 키보드 순서, 포커스 트랩, Escape 복귀, 44px 터치 목표를 자동 검사한다.
- 390px 모바일, 768px 태블릿, 1280px·1440px·1920px 데스크톱을 회귀 검증한다.
- 밝은/어두운 테마에서 선택·경계·상태 대비를 각각 확인한다.

## 완료 판단 기준

- 모바일 첫 화면에서 앱 바와 현재 작업 외의 전역 탐색이 상시 공간을 차지하지 않는다.
- 데스크톱 전역 셸은 108px 이내이며 작업별 명령과 명확히 구분된다.
- 어느 탭에서도 전역 탐색, 작업 명령, 상태 피드백이 같은 역할로 중복되지 않는다.
- 주요 흐름은 마우스·터치·키보드로 완료할 수 있고 가로 넘침이 없다.
