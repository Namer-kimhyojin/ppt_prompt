데이터 다이어그램 프롬프트 작성법

좋은 데이터 다이어그램 프롬프트는 장식보다 데이터의 의미를 먼저 고정합니다. 무엇을 비교하고 어떤 관계를 읽어야 하는지 정한 뒤 적합한 구조를 선택하세요.

다이어그램 설계
구조 선택 기준
  • 순서가 중요하면 프로세스
  • 연결이 중요하면 관계도
  • 차이가 중요하면 비교표
  • 비중이 중요하면 막대·도넛

작성·검토 PromptDeck최초 작성 2026-08-29최근 검토 2026-09-02예시 데이터는 설명용이며 원자료 대조가 필요합니다.

1. 다이어그램이 답할 질문을 한 문장으로 쓰세요

데이터를 모두 보여주려 하면 화면이 복잡해집니다. 먼저 “어떤 채널이 가장 많이 성장했는가”, “신청부터 선정까지 어떤 단계가 있는가”, “기관별 역할은 어떻게 연결되는가”처럼 독자가 확인해야 할 질문을 정하세요. 질문이 명확하면 강조할 값, 생략할 설명, 적합한 도식 유형을 결정하기 쉬워집니다.

2. 원본 데이터와 표현 지시를 구분하세요

프롬프트 안에서 확정된 값과 디자인 요청을 구역으로 나누면 AI가 숫자나 명칭을 임의로 바꾸는 일을 줄일 수 있습니다. 원본 데이터에는 단위와 기준 시점을 함께 적고, 빈 값이나 추정치에는 상태를 표시합니다. 값의 크기를 면적이나 길이로 표현할 때는 실제 비율을 유지하라고 명시하세요.

목적: 2025년과 2026년 채널별 문의 건수 비교
확정 데이터: 웹 120→186건 / 전화 95→82건 / 방문 44→51건
핵심 메시지: 웹 문의가 55% 증가해 가장 큰 변화
구조: 가로 그룹 막대 3쌍, 2025년 연회색, 2026년 코발트
레이블: 모든 막대 끝에 정확한 건수 표시, 단위는 건
금지: 값 재계산·반올림, 축 생략, 3D 원근, 관련 없는 장식
중요: 이미지 생성 모델이 숫자나 글자를 틀릴 수 있으므로, 수치가 핵심인 결과물은 SVG·차트 도구에서 만들거나 생성 후 반드시 원본과 대조하세요.

3. 목적에 맞는 도식 유형을 지정하세요

프로세스와 여정

단계 순서와 분기 조건이 핵심입니다. 시작·종료 지점, 단계 수, 진행 방향, 되돌아가는 경로를 적으세요. 화살표가 서로 교차하지 않도록 하고 각 단계의 동사형 제목을 짧게 유지합니다.

관계도와 조직도

노드의 등급과 연결 의미를 먼저 정의합니다. 실선은 지휘, 점선은 협력처럼 선의 의미가 둘 이상이면 범례를 포함하세요. 상하 관계가 없는 협력 기관을 위계적으로 배치하지 않도록 주의합니다.

비교와 비중

항목 간 차이는 공통 기준선에서 시작하는 막대가 읽기 쉽습니다. 원형이나 도넛은 전체가 100%인 소수 항목에만 사용합니다. 시각적 크기와 실제 값이 다르게 보이는 3D 표현은 피하세요.

4. 시선의 우선순위를 설계하세요

제목은 다이어그램이 전달할 결론을 말하고, 핵심 수치는 가장 높은 대비를 사용합니다. 보조 설명은 작은 크기와 낮은 채도로 구분하되 읽을 수 있는 대비를 유지하세요. 한 화면에서 강조색은 보통 한두 개면 충분합니다. 연결선, 테두리, 배경 장식이 데이터보다 강해지지 않도록 선 굵기와 색을 제한합니다.

검수 체크리스트
  • 원본의 모든 값과 단위가 일치하는가
  • 화살표 방향과 연결 관계가 논리적으로 맞는가
  • 색만으로 상태를 구분하지 않았는가
  • 범례 없이도 핵심 흐름을 이해할 수 있는가
  • 확정값과 예시·추정값이 명확히 구분되는가
