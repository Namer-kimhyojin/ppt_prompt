1. 언제 사용하는 스킬인가요?

원문을 단순 요약하는 대신, 청중이 내려야 할 판단을 중심으로 발표의 순서와 각 장의 역할을 설계할 때 사용합니다. 승인·보고·설득·제안·교육·질의 대응 자료에 적용할 수 있고, 특히 여러 문서와 수치를 한 덱으로 정리해야 할 때 유용합니다.

발표 기획형전략, 배분표, 슬라이드별 메시지, 스크립트와 제작 명세
PromptDeck 이미지 생성형공통 디자인 가이드와 결합할 슬라이드별 구조화 MD
통합형검토용 발표 기획안과 이미지 생성용 MD를 분리해 함께 제공
기본 원칙: 한 슬라이드에는 결론 하나만 두고, 원문에 없는 수치·사례·출처는 만들지 않습니다. 미확정 정보는 확인 필요로 표시합니다.

4. Codex에 스킬 등록하기

다운로드는 파일을 받는 단계이고, 등록은 Codex가 읽는 위치에 파일을 두는 단계입니다. 참고 규칙과 검증 스크립트가 필요하므로 SKILL.md 한 파일이 아니라 폴더 전체를 복사하세요.

  1. 압축 해제: Codex판 ZIP에서 ‘모두 압축 풀기’를 선택합니다. 안쪽의 ppt-slide-planner 폴더를 엽니다.
  2. 등록 위치 열기: Windows 파일 탐색기 주소창에 %USERPROFILE%\.agents\skills를 입력합니다. 경로가 없다면 사용자 폴더 안에 .agents, 그 안에 skills 폴더를 만듭니다.
  3. 폴더 복사: 해제한 ppt-slide-planner 폴더를 skills 안에 넣습니다. 기존에 직접 수정한 동명 스킬이 있다면 덮어쓰기 전에 별도 백업하세요.
  4. 구조 확인: 아래처럼 스킬 폴더를 한 번만 거쳐 바로 SKILL.md가 보여야 합니다. 파일 이름이 SKILL.md.txt가 아닌지도 확인하세요.

이전 경로를 사용 중이라면: 기존 안내의 .codex/skills에서 이미 인식되는 스킬은 중복 복사하지 마세요. 새 등록은 현재 공식 문서의 .agents/skills를 기준으로 안내합니다. 같은 이름을 여러 위치에 등록하면 선택기에 중복 표시될 수 있습니다.

5. Claude 스킬 등록·호출하기

Claude·Cowork: 계정에 ZIP 업로드

이 사이트의 Claude판은 사용자 제작 스킬입니다. Anthropic 공식 기본 스킬이나 설치형 플러그인 자체가 아닙니다. Claude판 ZIP을 그대로 업로드하고, 일반 대화창에 파일을 첨부하는 것과 구분하세요.

  1. 등록 화면: Claude의 Customize → Skills를 엽니다. 한국어 화면에서는 사용자 지정·스킬에 해당하는 메뉴를 찾으세요.

  3. 활성화: 목록의 ppt-slide-planner 스위치를 켭니다. 새 대화·Cowork 작업에서 원문을 첨부하고 아래처럼 요청합니다.

새 스킬이 보이지 않으면 세션을 다시 시작해 확인하세요. Claude Code의 로컬 폴더 등록과 Claude·Cowork 계정 등록은 다릅니다. Claude Code 공식 스킬 안내에서 실행 환경별 기준을 확인할 수 있습니다.

기존 플러그인 사용자는: 선택기에 보이는 이름을 그대로 사용하세요. $anthropic-skills:ppt-slide-planner는 이 제작 환경의 Codex 플러그인 호출 예시이지, Claude의 일반 ZIP 등록에 필요한 이름이 아닙니다. 플러그인 캐시 폴더를 직접 수정할 필요도 없습니다.
Claude판의 화면 표시 원칙: 슬라이드에 실제로 보일 텍스트는 STEP 6의 내용: 필드만 기준으로 삼습니다. 발표 대응 멘트, 다음 슬라이드 연결 문장, 기획 라벨은 〔화면 비표시〕로 분리합니다.

Claude에서 사용하지 않음업로드 후 활성화했는지 확인하고 새 대화에서 스킬명을 요청에 넣으세요. 대화창 첨부만으로는 등록되지 않습니다.

안전하게 시작하기: 스킬은 지시문과 실행 스크립트를 포함할 수 있습니다. 출처와 내용을 확인하고, 처음에는 민감정보 없는 샘플 문서로 시험하세요. 스킬 ZIP에는 유료 AI 이용권이 포함되지 않습니다.

7. 플랫폼별 작업 흐름

Codex판: C/V 추천안을 확정한 뒤 상세 설계

  1. 1
    원문과 요청 파악

    목적, 청중, 시간, 장수, 필수 내용과 검증된 수치를 먼저 고정합니다.

  2. 2
    발표 전략과 전체 구성

    청중의 최종 판단, 핵심 메시지 축, 예상 반론과 슬라이드 흐름을 설계합니다.

  3. 3
    배분표와 추천안 확인

    모든 슬라이드에 정보 밀도 C1~C4와 데이터 시각화 강도 V0~V4를 추천합니다.

  4. 4
    슬라이드별 상세 설계

    추천안 확인 뒤 메시지, 근거, 스크립트, 화면 큐와 제작 명세를 작성합니다.

  5. 5
    제작 경로로 인계

    Markdown 기획안, PromptDeck용 MD 또는 승인 후 실제 PPTX 제작으로 연결합니다.

중요한 확인 단계: 스킬은 상세 설계 전에 슬라이드별 C/V값과 표지·목차·간지·클로징 구현 추천을 먼저 보여줍니다. 추천안 적용 또는 03 C3/V3처럼 변경할 항목을 답해야 다음 단계로 진행됩니다.
설정낮음높음결정하는 것
정보 밀도 CC1 · 결론과 핵심 증거C4 · 표와 다차원 정보화면에 남길 근거·레이블·설명 깊이
데이터 강도 VV0 · 콘텐츠 중심V4 · 정밀 분석데이터의 주·보조 역할과 정확도 수준

Claude판: 스크립트에서 화면을 역설계

  1. 1
    산출물 유형과 공통 설정

    순차 발표형·Q&A 대응형·결론-서사형 중 하나와 밀도, 구역, 제목, 페이지 번호를 확정합니다.

  2. 2
    원문과 핵심 데이터 고정

    주장, 수치, 출처, 기준연도, 단위와 표본을 원문과 1:1로 대조합니다.

  3. 3
    발표 스크립트 작성

    Hook → Body(SCR) → Bridge 흐름으로 자연스럽게 말할 수 있는 완결 문장을 만듭니다.

  4. 4
    화면 큐 추출

    스크립트에서 보여줘야 할 문구, 수치, 차트, 전환 단서를 추출합니다.

  5. 5
    레이아웃·비주얼 명세

    큐를 크기·굵기·여백·대비로 계층화하고 슬라이드별 MD로 정리합니다.

L2 · 집중주요 주장, 전환짧은 메시지와 제한된 근거
L3 · 표준대부분의 본문메시지, 근거, 보조 설명의 균형
L4 · 정보표, 비교, 정밀 분석다차원 정보와 명시적 읽기 순서

8. PromptDeck과 함께 쓰는 방법

스킬과 PromptDeck은 같은 일을 반복하지 않습니다. 스킬이 슬라이드의 의미와 사실을 고정하고, PromptDeck이 덱 전체의 시각 언어를 제공하며, 이미지 AI가 허용 범위 안에서 최종 구도를 완성합니다.

1ppt-slide-planner논지, 표시 문구, 수치, 증거 지위, 의미 그룹과 관계를 정의
2PromptDeck덱 전체의 디자인 DNA, 색채, 타이포그래피, 형태와 프레임을 정의
3이미지 AI의미와 데이터를 지키며 구도·매체 후보를 비교해 완성 이미지를 생성
  1. 스킬에 PromptDeck 이미지 생성형 또는 통합형을 요청합니다.
  2. 슬라이드별 C/V값과 특수 슬라이드 추천안을 확인합니다.
  3. 생성된 {발표명}_promptdeck.md의 개별 슬라이드 명세를 준비합니다.
  4. PromptDeck에서 공통 디자인 가이드를 만든 뒤, 개별 슬라이드 MD와 결합해 생성합니다.

Claude판의 슬라이드 MD도 PromptDeck 작업 전 기획 입력으로 활용할 수 있습니다. 다만 PromptDeck 전용 표시·비표시 계약과 C/V값까지 자동으로 맞춘 파일이 필요하면 Codex판의 PromptDeck 이미지 생성형 또는 통합형을 선택하세요.

10. 결과를 받을 때 확인할 것

최종 점검표
  • 원문의 수치·날짜·출처·단위가 그대로 유지됐는가
  • 슬라이드 제목만 읽어도 주장과 근거가 이어지는가
  • 화면 문구와 발표자 메모가 분리됐는가
  • Codex판은 모든 장의 C/V값과 특수 페이지 구현안을 확인했는가
  • Claude판은 L1~L4 밀도와 STEP 6 내용: 표시 원칙을 지켰는가
  • 차트의 축, 범례, 기준연도, 표본과 출처가 빠지지 않았는가
  • 실제 PPTX가 필요하면 기획안 승인 후 프레젠테이션 제작 절차로 연결했는가

PDF·DOCX·PPTX·XLSX는 해당 형식을 읽고 검증할 수 있는 도구와 함께 사용합니다. HWP/HWPX를 안전하게 읽을 수 없는 환경에서는 임의로 해석하지 않고 PDF 또는 DOCX 변환본을 준비하는 것이 좋습니다.
